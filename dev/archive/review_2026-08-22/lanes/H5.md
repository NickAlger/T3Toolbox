# Lane H5 — uniform masks: phantom rank and garbage

Hunter lane over every uniform public op (`ut3_*`, `ufv_*`, `utv_*`, `UniformTuckerTensorTrain`,
`UT3Frame`/`UT3Variations`/`UT3Tangent`, `UT3Weights`/`UT3FrameWeights`, the two uniform geometries, the
uniform fitting kinds/optimizers). Repos scripts: `scratchpad/repros/H5/` (all run with the t3toolbox env,
`PYTHONPATH=/home/nick/repos/T3Toolbox`). Shared helpers in `h5lib.py` (`corrupt_*` = `1e3*randn` in the
padding through the object's own mask, real region untouched; `prefix`/`is_prefix`; `varying_stack`).

## What is sound (no finding)

- **Exact output masks on clean input** match the ragged ranks everywhere checked: t3svd (no caps, per-mode
  caps, per-stack-element caps on a variety stack), rank_adjustment_sweep, the four orthogonalizations
  (incl. per element on a varying-rank stack), sum_stack, squash_tails, `utv_to_ut3` (paper rule, honest
  boundaries), `utv_retract` (== ragged retract ranks, incl. per-element on varying C), `project_ambient`
  (gauge masks), `sum_tangents` (gauge masks / OR over C), `UT3Weights` concat/Kronecker.
  The only "mismatch" seen — `x + y` TT boundary ranks 1 (uniform) vs 2 (ragged) — is the documented
  uniform `__add__` squash, not a mask bug.
- **Gappy working-form masks** are handled correctly by every op that takes a plain UT3 (dense, norm/inner,
  sum, sampling + derivatives + corewise transposes (grads agree with ragged through the mask), to_t3,
  unstack/stack, sum_stack, reverse, the four orthogonalizations, t3svd → prefix output with ragged ranks,
  rank_adjustment_sweep, `UT3Weights.from_ut3svd`, unit-weight weighted norm, reciprocal). 
- **Garbage padding is inert** for: to_dense, apply_masks, reverse, scale, norm/inner (both paths), sum,
  entries/apply/probe + derivatives, the corewise (derivative) transposes, the four orthogonalizations (and
  their masks), is_left/right_orthogonal, t3svd (dense, svals, masks), rank_adjustment_sweep, to_t3,
  unstack/stack, save/load, ut3_orthogonal_representations, every weight op, and every tangent-layer op
  (frame checkers, to_dense, inner, gauge, project, project_oblique, retract, transport, project_ambient,
  sum_tangents, stack/unstack, corewise retract/inner, weighted norm/inner, to_t3tangent, normalized).
- Varying-rank stacks (the variety) are per-element correct in every op above.

## Findings

### H5-1 — S, confirmed. `ut3_squash_tails` sums the RAW boundary bonds (no mask): `squash_tails`, `+`, `-`, `sum_stack`, `UT3Frame.allclose`, `UT3Frame.is_consistent` read padding garbage.

`backend/ut3_operations.py:82` (`new_tt = tt_squash_tails(tt)` on the unmasked supercore). The summed
leading bond of core 0 / trailing bond of core d-1 includes the padded slots, which the contract declares
don't-care garbage. Every op that routes through it — `UniformTuckerTensorTrain.squash_tails`, `__add__`,
`__sub__`, `sum_stack` (`uniform_tucker_tensor_train.py:243/264/272`), and through `__sub__` also
`UT3Frame.allclose` (`uniform_frame_variations_format.py:256`) and `UT3Frame.is_consistent` (`:246`) —
returns a wrong tensor when the input's boundary-bond padding is nonzero. All mask-on-entry ops
(`norm`, `inner`, sampling, svd, ...) are fine on the same input.

Public path (no raw-`.data` construction needed): `UNIFORM_COREWISE.randn(frame)` fills the whole padded
variation supercore (documented: "filled completely; ungauged"), and `UNIFORM_COREWISE.retract` adds it
raw into the point. `repro_squash_public_path.py`:

```
corewise randn variation: tt padding nonzero? True  (bond-0 real rank 1, padded r=4)
retracted point tt[0] left-bond padding nonzero? True
y.to_dense()  vs  y.apply_masks().to_dense()  relerr: 0.0
(y + z).to_dense()        vs y.to_dense()+z.to_dense():   relerr = 1.622e+00
(y - z).to_dense()        vs y.to_dense()-z.to_dense():   relerr = 1.618e+00
(y + y).to_dense()        vs 2*y.to_dense():              relerr = 1.624e+00
y.squash_tails().to_dense() vs y.to_dense():             relerr = 1.624e+00
stack([y,y]).sum_stack()  vs 2*y.to_dense():              relerr = 1.624e+00
y.norm() vs dense norm  (masks on entry -> fine):         relerr = 1.600e-16
backend ut3_squash_tails: new G0[0] == sum over ALL padded left-bond slots (garbage included)? True
                          == sum over MASKED left-bond slots (the correct value)? False
squash(masked data).to_dense() == y.to_dense()? True
```
`repro_garbage_ut3.py` shows the same four ops failing (relerr 1e5..1e6 with 1e3 garbage) in all 16
structure/padding configs, and `repro_tangent.py` shows `frame.allclose` / `frame.is_consistent` failing on a
garbage-padded (but orthogonal, real-content-identical) frame. `tests/test_uniform_tucker_tensor_train.py::
test_padding_is_dont_care` only corrupts the Tucker padding and only checks `to_dense`, so it cannot see this.

Fix: in `ut3_squash_tails` multiply the two boundary bonds by their masks before summing (or call
`ut3_apply_masks` first — `_tt_squash_tails_uniform` is also used on already-masked data in `ut3svd`, so the
mask-once belongs in `ut3_squash_tails`). Add `squash_tails`/`+`/`sum_stack` to a garbage-robustness test
(the suite has none for the plain layer beyond `to_dense`).

### H5-2 — S, confirmed. `ut3_orthogonal_representations` on a NON-minimal-rank point builds frame masks from a rank recurrence that does not match the sweep it runs: the left-chain / down-core masks are too restrictive, the frame is not orthogonal on its masked block, the tangent space loses directions.

`backend/ufv_conversions.py:107` builds the prefix masks from `ranks.compute_orthogonal_representation_ranks`
(`backend/ranks.py:496`), whose recurrence is **right-then-left** (`:554` reduces the right chain against the
right neighbour, `:564` then derives the left chain from the *reduced* right ranks). The sweep it masks,
`fv_conversions.t3_orthogonal_representations` (`:123`; the documented Algorithm-11 divergence), is
**left-then-right**: its left chain keeps `min(rL·n, r_{i+1})` with the *original* bond, so at a non-minimal
TT bond the left chain (and the down core, whose left leg is the left bond) carries more orthonormal content
than the mask admits. On a minimal point the two orders agree; CLAUDE.md / `docs/uniform_equivalence_contract.md`
state the contract "holds on non-minimal-rank input too" and that minimal rank is a precondition for nothing.

`repro_nonminimal_rootcause.py` (x = randn((5,7,6),(2,3,2),(1,2,3,1)), bond 2 = 3 > n2·r3 = 2):
```
formula compute_orthogonal_representation_ranks: ((2,3,2), (2,3,2), (1,2,2,1), (1,2,2,1))
ragged T3Frame.from_t3 actual ranks:  up (2,3,2) down (2,3,2) left (1,2,3,1) right (1,2,2,1)
uniform left core 1 unmasked Gram (bond 2 columns): identity 3x3   -> 3 orthonormal columns exist; mask keeps 2
uniform down core 2 unmasked Gram over bonds: identity 3x3;  masked (2 rows) Gram: [[0.9955 -0.0068],[-0.0068 0.9897]]
  -> NOT orthonormal on the masked block; is_orthogonal() = False
MANIFOLD.norm(v) = 5.745542 vs dense HS norm of v.to_dense() = 5.737065   (frame claims orthogonal+gauged)
project_ambient(frame(x), z): uniform vs ragged relerr = 3.682e-02  (the projection is unique; they must agree)
Safe mode: UNIFORM_MANIFOLD.randn(UNIFORM_MANIFOLD.frame(x)) -> ValueError "requires an orthogonal frame"
frame(x + y).is_orthogonal() = False ; ragged T3Frame.from_t3(x+y).is_orthogonal() = True
```
`repro_nonminimal_frame.py` adds the `uniform_fitting` doctest's own non-minimal example ((6,6,6),(2,2,2),(1,3,3,1)):
residual 2.1e-2, `to_t3frame().is_orthogonal()` False; and a non-minimal *Tucker* rank case (3 > r0·r1) which is
fine (the Tucker recurrence matches). `repro_gappy.py`: `UNIFORM_MANIFOLD.frame(x + y)` is non-orthogonal in every
case (residuals 1.4e-4 .. 2.1e-1) — sums are the everyday non-minimal input.

Consequences: in safe mode every manifold op on the library's own frame raises an obscure "requires an
orthogonal frame" (a user cannot fix it — the frame came from `UNIFORM_MANIFOLD.frame`); in unsafe mode /
under jit `project`, `project_ambient`, `transport`, `inner`/`norm` and `retract` silently compute in a
smaller-than-true tangent space (3.7e-2 relative error on the unique ambient projection above). The fitting
path is shielded by `uniform_minimal` (it reduces first), so `newton_cg` etc. are unaffected.

Fix: make the mask builder follow the sweep actually run — either compute the frame ranks with the
left-then-right recurrence (left: `min(rL·n, r_{i+1})` on the original bonds, right from the left chain),
or run the sweep right-then-left as the paper does so the existing formula is right. Add a non-minimal
structure (e.g. (1,2,3,1) TT with (2,3,2) Tucker, and an `x + y`) to `tests/test_uniform_manifold.py`
`_CONFIGS` with `frame.is_orthogonal()` + `project_ambient` vs ragged assertions.

### H5-3 — C, confirmed. d = 1 uniform: `_tt_squash_tails_uniform` duplicates the single core, so squash/+/−/sum_stack/norm/inner/t3svd/rank_adjustment_sweep/left+right orthogonalize/is_left_orthogonal/ut3_orthogonal_representations all crash; ragged d = 1 works throughout.

`backend/tt_operations.py:114`: `concatenate([tt[:1], tt[1:-1], tt[-1:]])` — for d = 1 the first and last
slices are the same core, so the output has 2 cores. `repro_d1_ops.py`:
```
backend _tt_squash_tails_uniform on a d=1 supercore: in shape (1,1,3,1) -> out shape (2,1,3,1) (d doubled!)
squash_tails / x + y / x - y / stack.sum_stack   CRASH ValueError: Inconsistent UniformTuckerTensorTrain: tt_supercore.shape = (2, ...), expected (1, ...)
norm() / inner(y) / left_orthogonalize_tt_cores / right_orthogonalize_tt_cores  CRASH ValueError: all the input arrays must have same number of dimensions ...
t3svd() / rank_adjustment_sweep  CRASH ValueError: ... along dimension 0, the array at index 0 has size 2 ...
is_left_orthogonal               CRASH ValueError: zero-size array to reduction operation maximum   (ut3_orthogonality_residual.py:63, tt_sc[:-1] is empty for d=1)
ut3_orthogonal_representations   CRASH ValueError: Inconsistent shapes for UT3Frame ...
to_dense / entries / apply / probe / sum / down_orth / up_orth / norm(use_orthogonalization=False)  OK
ragged x.squash_tails / x+y / x.t3svd / x.norm (d=1)   OK
```
Nothing in the docs excludes d = 1 from the plain uniform layer (only `utv_to_ut3` documents a d ≥ 2
restriction). Fix: in `_tt_squash_tails_uniform` handle d = 1 by applying both boundary sums to the one
core (`new_G0` then `new_Gf` on the result; concatenate only when d ≥ 2); guard the empty interior-bond
reduction in `ut3_orthogonality_residual` (return the Tucker residual when d = 1).

### H5-4 — C + D, confirmed. A minimal-rank but slack-padded `x0` (`from_t3(x, n=, r=)`) passes `uniform_minimal` / the optimizer's minimal-rank check, but `utv_retract` → `ut3svd` shrinks the padded dims to `max(raw ranks)`, desyncing the loop-invariant masks: every uniform manifold optimizer crashes with a numpy broadcast error at the second step. The `utv_retract` docstring ("the output is a UT3 at the frame padded dims") is false for such frames.

`backend/ut3_svd.py:111-116` slices the result to `n2 = max(raw_tucker)`, `r2 = max(raw_tt)`;
`backend/utv_operations.py:326-328` claims the retract output is at the frame padded dims; the uniform
optimizers hold `x0.masks` loop-invariant (`backend/uniform_fitting.py:431` only checks rank minimality).
`repro_slack_padding_optimizer.py` (x0 minimal ranks (2,3,2)/(1,2,2,1), padded n=5, r=4 — a documented
`from_t3` option, "pass to force a larger pad"):
```
=== x0 padded n=5 r=4 (max real ranks 3,2); minimal? True; uniform_minimal returns same object? True
  frontend retract of zero tangent: output (n, r) = (3, 2); frame (nU, rL) = (5, 4); x0 (n, r) = (5, 4)
  newton_cg / mc_sgd / adam / backend gradient_descent  CRASH ValueError: operands could not be broadcast together with remapped shapes ... (3,3,7) ... (3,5)
  newton_cg COREWISE  OK        (additive retraction keeps the padded shape)
=== x0 padded n=3 r=2 (tight): everything OK
```
`repro_tangent.py` flags the docstring claim on every forced-pad config (`retract output padded dims ==
frame padded dims ... FAIL got n,r=3,2 frame nU,rL=5,5`). Fix: either have `ut3svd`/`utv_retract` keep the
input padded dims (no `[:n2]`/`[:r2]` slice when called from retract — the masks already carry the ranks), or
make `uniform_least_squares_problem` / the frontend optimizers reject or re-pad a slack-padded `x0`
(`x0.n > max(tucker_ranks)` or `x0.r > max(tt_ranks)`) with a clear message, and fix the docstring.

### H5-5 — E (spurious structural error), confirmed. `safety.frames_equal` compares the raw frame supercores including the padding, so two frames identical on their real (masked) content but different in padding are "different tangent spaces".

`safety.py:208/227` (`_arrays_allclose` over `frame.data[:4]`, no masking). `repro_tangent.py`: a garbage-padded
copy of a frame (real content bit-identical, `is_orthogonal` True, `to_dense` equal) makes
`UT3Tangent.__sub__`/`allclose`/`stack_tangents` raise
`Tangent vectors are in different tangent spaces (their frames are not the same frame)`. Reachable only by
raw construction or by mixing a frame with a re-padded copy, so low priority; fix by masking both frames
(`ufv_apply_frame_masks`) before the compare in the uniform call sites, or documenting that frame equality is
on the stored supercores.
