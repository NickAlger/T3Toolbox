# Lane H6 — preconditions, safety mode, error messages

Hunter lane. Bug class: (a) numerical preconditions enforced other than where `docs/numerical_contracts.md` /
`docs/contributor/numerical_contract_catalog.md` say; checks that do not skip under `safety.unsafe()` / a jax
trace; wrong tolerance selection; stale cached residuals; the same-frame guard under stacks and jit round-trips;
(b) every `__post_init__`/`validate()` contract; (c) every `raise` in the library; (d) the safety module itself.

Repro scripts: `scratchpad/repros/H6/` (all run with the t3toolbox env Python, `PYTHONPATH=/home/nick/repos/T3Toolbox`).

## Method

1. Mechanical enumeration: `grep` for `checks_active` / `safety.require` / `frames_equal_or_skip` /
   `effective_rtol` (33 call sites in 7 modules), `def validate` / `__post_init__` (15 classes), and `raise `
   (194 sites, dumped with context to `repros/H6/raises_dump.txt`).
2. Catalog-vs-code table: for every op with a claimed precondition, a violating input was run in safe mode
   (expect raise), under `safety.unsafe()` (expect pass) and under `jax.jit` (expect pass); ops the catalog
   calls precondition-free were run on violating inputs to confirm no raise. Ragged (`repro_catalog_ragged.py`),
   uniform (`repro_catalog_uniform.py`), shared geometry + `GaussNewtonModel` (both scripts).
3. Structural contracts: one wrong-shape input per branch of every `validate()` (`repro_structural.py`).
4. Safety module: trace detection under jit/vmap/grad with closed-over numpy and jax operands, thread
   inheritance of `set_default_safety`, nesting/restoration on exception, `effective_rtol` on mixed inputs,
   `frames_equal` semantics (`repro_safety_module.py`).
5. Tolerance semantics: scale dependence of the GAUGE check (`repro_gauge_scale.py`, plus the jax-eager block
   in `repro_catalog_ragged.py`).

Tolerance selection: `effective_rtol` picks `rtol_jax` when any operand is jax (mixed numpy frame + jax variations
→ `1e-5`), `rtol_numpy` otherwise — as documented. Cached residuals (`T3Frame.orthogonality_residual`,
`T3Tangent.gauge_residual`) are `functools.cached_property` on frozen dataclasses: they are computed once per
object, and a jit round-trip / `dc.replace` builds a new object (recompute, never stale). The same-frame guard on
stacked frames differing in one stack element raises (all-elements compare), and value-equal copies pass.

## Findings

### H6-1 (S, confirmed) — `UNIFORM_MANIFOLD.frame(x)` is not orthonormal when a TT core's *right* unfolding is rank-deficient
`t3toolbox/backend/ufv_conversions.py:60` (`ut3_orthogonal_representations`), reached via
`t3toolbox/uniform_frame_variations_format.py:296` (`UT3Frame.from_ut3`) and `t3toolbox/uniform_manifold.py:1027`.

For `x = TuckerTensorTrain.randn((4,5,3), (2,3,2), (1,2,3,1))` (r2 = 3 > n2 = 2, the last core is
right-rank-deficient) the ragged frame `MANIFOLD.frame(x)` has orthogonality residual 8e-16, but
`UNIFORM_MANIFOLD.frame(UniformTuckerTensorTrain.from_t3(x))` has residual 2.5e-1 (`is_orthogonal()` False; the
extracted `to_t3frame()` shows the down core D[2] gram deviating by 0.99). Same for
`((3,3,3,3),(2,2,2,2),(1,2,2,3,1))` (r3 = 3 > n3·r4 = 2): residual 6.6e-2. Left-deficient cases (r1 > n0,
r2 > r1·n1) are fine, as are minimal ranks and non-minimal Tucker ranks. Consequences:
- safe mode: `UNIFORM_MANIFOLD.randn/project/retract/...` on this frame raise the ORTH precondition, and the
  message says "Build the frame with UniformManifoldGeometry.frame" — which is what the user did (not actionable);
- unsafe mode / jit: `UNIFORM_MANIFOLD.project_ambient(ufr, g)` differs from the ragged result by 1.1e-2 and
  1.1e-1 relative (vs 6e-16 on minimal input) — a silent wrong answer that breaks
  `docs/uniform_equivalence_contract.md:33` ("The contract holds on non-minimal-rank input too").
The fitting entry point guards this (`backend/uniform_fitting.py:431` "requires a minimal-rank frame x0"), but the
geometry's `frame` does not. Repro: `repro_uniform_frame_orth.py`, `repro_uniform_frame_orth2.py`.
Fix: make the right/down uniform orthogonalization sweep rank-aware like the left one (SVD-prefix completion at
the zero-σ slots, per `docs/contributor/uniform_svd_prefix_orthogonalization.md`), or reduce to minimal
structural ranks inside `from_ut3`; at minimum raise a clear structural error in `UT3Frame.from_ut3`.

### H6-2 (C, confirmed; with an S facet) — the GAUGE check thresholds an absolute residual at a relative tolerance
`t3toolbox/manifold.py:547` (`is_gauged`) / `:1296-1301` (`MANIFOLD.inner`) / `:1314-1319` (`MANIFOLD.norm`);
the residual is `backend/tv_operations.py:603` (`tv_gauge_residual` = max |UᵀV|, which scales with ‖V‖);
uniform twins at `uniform_manifold.py:1113-1137`. The check sites pass `safety.effective_rtol(...)` (a *relative*
tolerance, 1e-9 / 1e-5) as `atol=` to `is_gauged`.
- False failures: a correctly gauged tangent (`MANIFOLD.randn(frame) * s`, gauge preserved exactly by
  linearity; relative residual 1.5e-16 at every scale) makes `MANIFOLD.norm` raise "requires gauged variations"
  at s ≥ 1e8 in numpy, and at **s ≥ 1e2 in jax eager float32** (`gauge_residual` 1.8e-5 > 1e-5) — the documented
  jax-but-not-jit autodiff-prototyping use. Gradient/step norms of 1e2–1e8 are ordinary in fitting.
- Silent pass: an ungauged random tangent scaled by 1e-10 has residual 2.5e-10 ≤ 1e-9, so `is_gauged()` is True
  and `MANIFOLD.norm` returns 7.01e-10 while the true HS norm of the realized tensor is 6.78e-10 (3.5% off).
The ORTH residual (gram vs identity) and the TIED residual (`t3_sharing_residual`, relative by construction) do not
have this problem. Repro: `repro_gauge_scale.py`; jax block at the end of `repro_catalog_ragged.py`.
Fix: make `tv_gauge_residual`/`utv_gauge_residual` relative (divide by the per-element variation norm, or
threshold at `rtol · corewise_norm` in `is_gauged`), and document it as relative like the tied residual.

### H6-3 (D, confirmed) — `shared(…).frame(x)` is documented as a TIED precondition but ties silently
`docs/numerical_contracts.md:86` ("`shared(…)` wrapper: `frame(x)`, `transport(v, new_frame)` | **TIED**") vs
`t3toolbox/shared_geometry.py:165-181` ("An untied ``x`` is tied first, silently, by the per-group mean"). Verified
ragged and uniform: `shared_manifold(sh).frame(untied_x)` passes in safe mode. Fix: move `frame(x)` out of that row
(it is an entry point like `x.share`), keep `transport` there.

### H6-4 (S, confirmed, low severity) — a *structural* tangent mismatch is only caught by the *numerical* guard
`t3toolbox/manifold.py:357` (`_check_same_tangent_space`), `t3toolbox/fitting.py:108` (`_require_at_frame`).
Two tangents at frames of different rank structure (holes `((2,4),(2,5),(2,3))` vs `((1,4),(1,5),(1,3))`, TT holes
`(1,2,2)…` vs `(1,1,1)`) are rejected in safe mode with "Tangent vectors are in different tangent spaces … run
inside safety.unsafe() to skip this numerical check". Following that advice, `a + b` under `safety.unsafe()`
returns a `T3Tangent` with `a`'s structure (numpy broadcasting) and `a.corewise_inner(b)` returns -1.309 — no
error. With non-broadcastable holes it fails with a raw numpy broadcast error / jax `TypeError` instead. This
contradicts "Structural problems always error, in both modes" (`docs/user_guide.rst:325`, `CLAUDE.md`). The
uniform twin is fine (its mask-equality check is structural and always runs). `GaussNewtonModel` under unsafe
raises a raw einsum size error. Repro: `repro_shared_followups.py` section (3), `repro_structural_vs_numerical_guard.py`.
Fix: in `_check_same_tangent_space` / `_require_at_frame` check `frame.variation_shapes` (and stack shapes)
equality unconditionally before the numerical compare, and word the structural message without the unsafe-mode hint.

### H6-5 (C, confirmed) — stacked `T3Frame` Tucker-rank error message prints the wrong numbers
`t3toolbox/frame_variations_format.py:499-501`: the condition compares `shape[-2]` but the message prints
`U.shape[0]`, `L.shape[1]`, `R.shape[1]`. For a stacked frame `(2,)` with `U0` of shape `(2, 9, 4)` the message reads
"U.shape[-2]=2, L.shape[-2]=1, R.shape[-2]=1" (actual 9, 2, 2). Unstacked it happens to be right.
Repro: `repro_structural.py` ("tucker rank U vs L (STACKED)"). Fix: print `shape[-2]`.

### H6-8 (C, confirmed, minor) — `set_default_safety(None, None)` is accepted and then every check crashes
`t3toolbox/safety.py:107`. There is no script-level way to set *unsafe* as the default (`unsafe()` is only a
context manager); `set_default_safety(None, None)` is the obvious attempt, is accepted, and `checks_active` stays
True while `effective_rtol` returns None → `MANIFOLD.norm` fails with `TypeError: '<=' not supported between
instances of 'float' and 'NoneType'`. Repro: `repro_structural_vs_numerical_guard.py` (last block).
Fix: treat `None` as unsafe (mirror the ContextVar's own convention) or validate the arguments.

### H6-9 (D, confirmed, minor) — `set_default_safety` "script-level default" is not seen by threads
`t3toolbox/safety.py:107-110`. `ContextVar.set` applies to the current context only; a `threading.Thread` started
afterwards sees `SafetyTolerances(1e-09, 1e-05)` after the main thread set `(1e-3, 1e-2)`. The docstring's
"script-level default" is misleading for threaded scripts (asyncio tasks do inherit). Repro: `repro_safety_module.py` §3.
Fix: document, or keep a module-level default that the ContextVar falls back to.

### H6-10 (D, confirmed, trivial) — `T3Tangent.__add__/__sub__` docstrings say "same T3Frame object"
`t3toolbox/manifold.py:371, 376`. The guard is the numerical `frames_equal` (a value-equal copy passes, verified);
the docstrings still describe the retired identity guard.

### H6-11 (C, confirmed, low) — `GaussNewtonModel` constructors do no structural validation of sample vs point
`t3toolbox/fitting.py:480` (`apply_model`; same for the others). `apply_model(MANIFOLD, x, ww, r[:5])` (W mismatch)
fails at `.gradient` with "Size of label 'c' for operand 2 (5) does not match previous terms (6)"; `ww[:2]` (wrong
d) with a bare `IndexError: list index out of range`; a wrong `Ni` with a numpy broadcast error. Repro:
`repro_structural.py` (last section). Fix: validate `len(ww) == d`, `ww[i].shape[-1] == N_i`, `residual.shape == W + C`
at construction with a named message.

### H6-12 (E, confirmed) — `jax.core.trace_state_clean` does not exist in jax 0.10.2; the docstring overstates `_inside_jax_trace`
`t3toolbox/safety.py:137-157`. The primary detector raises `AttributeError` on every call and the probe fallback
(`jnp.zeros(1) + jnp.zeros(1)` is a tracer iff tracing) carries the feature — it works under `jit`, including the
closed-over-concrete-jax-frame case (`jit(MANIFOLD.project)` with a concrete jax frame: OK). But the docstring
"True iff we are currently inside *any* jax transform (jit / grad / vmap), independent of the inputs" is not what
the probe does: under `vmap`/`grad` with concrete operands it returns False and the checks run (harmless — the
operands are concrete, so `bool()` works). Repro: `repro_safety_module.py` §1. Fix: drop the dead primary path (or
use `jax.core.trace_ctx`/the current public equivalent) and narrow the docstring to jit.

## Coverage
- 33 `safety.*` call sites enumerated and each exercised (safe / unsafe / jit) on ragged, uniform, shared and
  fitting surfaces; 14 jitted ops confirmed to skip checks; jax-eager tolerance selection confirmed.
- 15 `validate()`/`__post_init__` contracts: 45 wrong-shape constructions, all raise (the one "accepted" case — a
  down core with a different middle dim — is a legitimate free rank store, not a bug).
- 194 `raise` sites read (dump in `repros/H6/raises_dump.txt`); grep for `T3Base`, `wt3_`, `EdgeVectors`,
  `WeightedTuckerTensorTrain`, `UniformGaussNewtonModel`, `outer_tt_cores`, `dev/`.
- Safety module: trace detection (jit/vmap/grad, numpy/jax, closed-over), thread inheritance, nesting + exception
  restoration, `effective_rtol` on mixed trees, `frames_equal` atol=0 semantics (exact zeros must match exactly —
  noted, not a finding: the jit round-trip is bit-exact).
- Cached residuals: cached_property on frozen dataclasses, recompute on new objects, no staleness path short of
  in-place mutation of a core array.
