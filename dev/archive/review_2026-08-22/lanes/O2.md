## Method

An **independent dense oracle** (`oracle.py`) implements all six sampling kinds from `to_dense()` with hand
einsums; the derivative kinds are recovered by *exact polynomial interpolation* of `S(X; ww + s·pp)` in `s`
(degree `d` for apply/entries, `d−1` for probe) at Chebyshev nodes — no library jet code is involved. The
oracle was first validated against the library's plain ops (`sanity_oracle.py`: 108/108 agree to <1e-9
over d∈{1,2,3}, W∈{(7,),(3,4)}, orders 1–3). The residual weight `ω[mode, order]` and the regularizer
`ρ(x)` (`½λ‖X‖²_HS` on MANIFOLD via the dense norm; `½λΣ‖core‖²` on COREWISE) are likewise computed by hand.

Problem sizes: d=3 `(4,5,6)/(2,3,2)/(1,2,2,1)` (asymmetric; minimal), shared d=3 `(4,4,6)/(2,2,2)` with
sharing `(0,0,1)`; d=2 `(4,5)/(2,2)/(1,2,1)` and shared `(5,5)/(2,2)` with `(0,0)`; d=1 `(5,)/(3,)`; W=12 or
(3,4); λ=0.3.

| gn_quadratic | vs `‖ω⊙Jp‖² + λ‖Πp‖²` | 1e-8 | 992/992 |

### Part 2 — the four frontend optimizers (`sweep_optimizers.py`, 352 cases, ~4 min)

Axes: d {3,2} × rep × 4 geometries × 6 kinds (order 2) × weight × regularizer. Per case: `newton_cg`
(3 iters, `callback` capturing `x_cores`): every `NewtonInfo.objective` / `misfit` / `regularization` and
every `stats['history']` row equals the hand recomputation at that iterate, and `objective == misfit +
regularization` exactly; `gradient_descent`: `losses[0]` = hand objective at x0 and `losses[3]` (of a
4-iteration run) = hand objective at the point the 3-iteration run returns; `mc_sgd` (`max_iter=check_every`)
and `adam` (`max_iter=50`): the single reported full-batch loss equals the hand objective at the returned
point. Ragged-vs-uniform: `newton_cg` / `gradient_descent` losses and dense iterates agree to <1e-7 for every
(geometry, kind, weight, reg). **Result: 352/352 pass** on minimal-rank starts (the first run used a
non-minimal d=2 structure by accident, which is how finding O2-1 surfaced).

### Part 3 — jit, chunking, stacked x0, x0 variants, display, d=1 (`sweep_misc.py`)

- **jit == eager (x64):** `newton_cg` and `mc_sgd` agree to ≤6e-14 in losses and dense result for all
  {ragged, uniform} × {MANIFOLD, COREWISE, shared MANIFOLD} × {apply, probe+mode-weight,
  probe_derivatives+matrix, entries_derivatives+order} × {reg, no reg} (the jit result is float64 as
  documented). `adam` agrees to 1e-16 on COREWISE but differs by **2e-3 … 4e-2 on every MANIFOLD case**
  → finding O2-2 (not a jit issue: numpy-eager vs jax-eager already differ, see below).
- **chunk_size** (uniform + ragged, probe_derivatives order 2, W=12, eager and jit): `None`/`'auto'`/`5`/`1`/
  `100` give identical `newton_cg` trajectories (≤1e-14). Ragged ignores it as documented.
- **stacked x0:** all four optimizers raise `NotImplementedError` for a stack `C=(2,)`, ragged and uniform,
  *before any work* (verified by passing a sample with the wrong W — a real forward would have raised a shape
  error instead). Stacked + regularizer on the model path raises too.
- **x0 variants** (MANIFOLD, apply): random, left-orthogonalized, zero, and a non-minimal start. Random and
  orthogonalized agree ragged-vs-uniform to all printed digits for newton_cg/gradient_descent/mc_sgd; the
  zero start diverges across layers as §4.11 documents. The non-minimal start runs on newton_cg /
  gradient_descent / mc_sgd (ranks drop to minimal on the first retraction) but **`adam` crashes** → O2-1.
- **`verbose=True` + `val_sample`/`val_data` + regularizer**: ragged and uniform, probe / probe_derivatives /
  apply: records returned in `stats['diagnostics']`, history rows carry `misfit`/`regularization`.
- **d=1 ragged**: all five kinds × both geometries run on `newton_cg` and descend (uniform d=1 is the known
  ledger deferral; not re-tested).
- **Minibatch `take` invariant** (`check_take.py`): for every kind, both layers (packed uniform take), W=(12,)
  and (3,4): `S(A; sample_B) == data_B` exactly for the drawn minibatch.
- **Known S (reg at a raw non-left-orthogonal x0)** — consequence measured: `Problem.objective(raw x0)` =
  84.04 vs hand 245.60, but `LocalModel.objective` = 245.60 (correct) and `gradient_descent` `losses[0]` =
  245.599525 (correct). The optimizer loops only ever call `Problem.objective` on retracted (left-orthogonal)
  points, so the wrong value is confined to a direct backend call on a raw point. Not broader than described.

## Findings

### O2-1 (C, confirmed) — `adam` on a ragged MANIFOLD x0 with non-minimal ranks crashes at step 2 with a bare broadcast error
`t3toolbox/backend/optimizers.py:483` (`m = cw.corewise_zeros_like(cores)`); `t3toolbox/optimizers.py:193–203`
(the ragged `_setup` branch does no minimal-rank reduction, unlike the uniform branch at :186).
Repro `repros/O2/repro_nonminimal_ragged.py`: d=2 `(4,5)/(2,3)/(1,2,1)` (`has_minimal_ranks == False`):
```
newton_cg OK ranks -> (2, 2) (1, 2, 1)
gradient_descent OK ranks -> (2, 2) (1, 2, 1)
mc_sgd OK ranks -> (2, 2) (1, 2, 1)
adam RAISED ValueError operands could not be broadcast together with shapes (3,5) (2,5)
```
Mechanism: the Adam moment trees `m`/`v` are allocated at x0's core shapes; the first manifold retraction drops
the redundant rank (the documented caveat), so the second step's `corewise_map(m, g)` sees mismatched core
shapes. The other three optimizers rebuild everything per step and survive. Supported path: the frontend says
`x0: initial point (any cores; the geometry orthogonalizes internally)` and the uniform twin reduces
transparently; the d=3 analogue `(2,3,2)/(1,2,1,1)` reproduces it too (`sweep_misc.out`, "nonminimal ragged
adam"). Fix: reduce a ragged x0 to minimal ranks in `_setup` (mirror of `uniform_minimal`, e.g. `t3svd` +
`rank_adjustment_sweep('right_to_left')`), or rebuild `m`/`v` with `corewise_zeros_like` when the retracted
core shapes change, or reject non-minimal x0 with a clear message.

### O2-2 (D, confirmed) — `adam` on MANIFOLD is gauge-dependent: numpy-eager, jax-eager, jit, ragged and uniform all give different iterates
`t3toolbox/backend/optimizers.py:455` (`adam`), vs `docs/fitting_and_optimization.md:14` ("4 optimizers × 2
geometries") and `:288–290` ("a single kernel runs numpy-eager, jax-eager, or jit-compiled").
Repro `repros/O2/repro_adam_manifold_gauge.py` (x64, 50 steps, apply, d=3):
```
MANIFOLD: ragged numpy-eager vs jax-eager 5.7e-03 | vs jit 6.5e-03 | ragged vs uniform (numpy) 6.9e-03
COREWISE: ragged numpy-eager vs jax-eager 2.5e-16 | vs jit 4.6e-16 | ragged vs uniform (numpy) 1.6e-16
newton_cg MANIFOLD: eager vs jit 7.2e-15, ragged vs uniform 5.8e-15
```
Mechanism: Adam's `m`/`v` are accumulated in the coordinates of the current orthonormal frame, which is
re-chosen every step by an SVD whose sign/gauge convention differs between numpy and jax and between the
ragged and uniform orthogonalizations; nothing transports the moments, so the algorithm is not a function of
the point. Every other optimizer (and adam on COREWISE) is gauge-invariant to ~1e-15. Not a silent wrong
answer in the strict sense (each run is a valid descent), but the reproducibility promises above do not hold
for this cell, and adam's docstring only says "intended" for corewise. Fix: document the caveat in the adam
docstrings + §2.4/§4.5 (or warn/raise on a manifold geometry), or transport/reset the moments per step.

### O2-3 (D, confirmed) — `GaussNewtonModel.jacobian` / `residual` shape comments omit the uniform PACKED layout
`t3toolbox/fitting.py:334` (`probe: len=d, elm_shape=W+C+(Ni,)`) and `:265` (`residual … len=d, W+C+(Ni,) (probe)`).
Repro `repros/O2/repro_small_docs.py`:
```
ragged jacobian (probe): tuple [(12, 4), (12, 5), (12, 6)]
uniform jacobian (probe): ndarray (3, 12, 6)  (docstring: len=d, elm_shape=W+C+(Ni,))
uniform residual field: ndarray (3, 12, 6)
```
A uniform model returns the packed `(d,)+W+C+(N,)` array (zero-padded; verified) — the `sample` field comment
says "(uniform: PACKED)" but `residual` and the `jacobian` return comment do not. Fix: add the packed form to
both comments (same for the `(order+1)` derivative layouts: `(d,)+(order+1,)+W+C+(N,)`).

### O2-4 (E, confirmed) — `gradient_descent` has no `use_jit` and its docstring does not say so
`t3toolbox/optimizers.py:212–230`. `topt.gradient_descent(..., use_jit=True)` → `TypeError: got an unexpected
keyword argument 'use_jit'` (from the backend, via `**kwargs`). The module docstring (:24) scopes `use_jit` to
the other three, so this is consistent, just unstated on the function. One-line docstring note.

## Not found (negative results worth recording)
- No wrong objective / gradient / Hessian / quadratic form in any of the 992 model cases or 352 optimizer
  cases, including every weight layout on every kind and layer, the shared geometries (manifold and corewise,
  ragged and uniform), and W=(3,4).
- `stats`/`history` values are exact at every iterate for all four optimizers; `obj = misfit + reg` holds.
- `chunk_size` never changes a result; `'auto'` resolves without error on both layers.
- Stacked-x0 rejection is at entry for all four optimizers and both layers.
