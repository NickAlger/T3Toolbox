# Lane R2 — ragged backend core

Scope: `t3toolbox/backend/{t3_constructors,t3_conversions,t3_operations,t3_linalg,t3_orthogonalization,tt_operations,tt_orthogonalization,linalg,common,contractions,stacking}.py` (4,248 lines, all read in full), plus `docs/grouped_contractions.md`, `docs/contributor/contractions_internals.md`, `docs/contributor/batching_internals.md`, and the stacking half of `docs/batching_and_stacking.md` (§1, §5, §6, §7).
Repro scripts: `scratchpad/repros/R2/r2_01..r2_14*.py` (run with the env python, `PYTHONPATH=/home/nick/repos/T3Toolbox`, from the repro dir).

## Method

Every public function in scope was read against its docstring, signature shape-comments and its delegates' signatures. Nontrivial contracts were then checked by script against dense ground truth (`t3_to_dense` + explicit `np.einsum`), using the asymmetric-shape rule from the brief: distinct mode sizes, distinct Tucker and TT ranks, non-square cores, `d ∈ {1,2,3,4}`, `stack_shape ∈ {(), (2,), (2,3)}`, and boundary TT ranks both 1 and ≠1. Gauge-invariant comparisons only (represented tensors, residual norms, orthogonality residuals).

## Findings (detail)

### R2-1 — S, confirmed. `t3m_swap` is silently wrong when both inputs have equal boundary TT ranks ≠ 1, and crashes when they differ
`t3_linalg.py:552-557`. `t3m_swap` builds the length-2d chain `Gx_o + reversed(Gy_o)` and merges the seam pair `(d-1, d)` with `_t3m_contract_pair`, whose `einsum('...anb,...bmc->...anmc')` **contracts** `Gx`'s trailing bond `rd_x` against `Gy`'s trailing bond `rd_y`. The represented-tensor semantics (`to_dense`, `t3_inner_product`, `t3_mult`) sum each boundary bond with a ones vector separately. With `rd_x == rd_y == 2` the contraction runs and returns a wrong product (relerr 0.50 and 0.65 in the repros); with `rd_x != rd_y` numpy raises a broadcast `ValueError` from inside the einsum. `form_then_round` and `inplace_fused` are correct on the same inputs (fused returns an unusual trailing rank `rd_x*rd_y`, value correct). `TuckerTensorTrain.validate` allows `r0, rd != 1` (the class docstring says "You can make r0=rd=1 using squash_tails"), and `t3m` checks only `shape`/`stack_shape`. Supported path: `x.segment(1,3).t3m(y.segment(1,3), method='swap', max_tt_ranks=...)` (`r2_13`), or `randn` with user tt_ranks (`r2_03`). `tests/test_t3m.py` only uses structures with `tt_ranks[0]==tt_ranks[-1]==1`, so this is invisible to the suite.
Fix: squash tails of both operands at the top of `t3m_swap` (`tt_squash_tails`), or in `TuckerTensorTrain.t3m` for all three methods; add an unsquashed structure to `test_t3m.STRUCTURES`.

### R2-2 — S, confirmed (minor). `t3m_swap` silently ignores a per-position `max_tt_ranks` given as a numpy array
`t3_linalg.py:573-574`: `need_cleanup = (oversample > 1) or (isinstance(max_tt_ranks, typ.Sequence) and ...)`. A numpy array is not a `typ.Sequence`, so the final `t3svd` cleanup (the only mechanism that honors per-position bonds in the swap method, per the docstring) is skipped; `ranks.normalize_max_ranks` accepts the array, so nothing raises. `A.t3m(B, method='swap', max_tt_ranks=np.array([1,2,3,2,1]))` returns `tt_ranks=(1,3,3,3,1)`; the list form returns `(1,2,3,2,1)`; `inplace_fused` honors the array (`r2_13`). Fix: test `np.ndim(max_tt_ranks) > 0` (or `not isinstance(max_tt_ranks, (int, np.integer, type(None)))`).

### R2-3 — D, confirmed. `linalg.truncated_svd` (and every directional/pair wrapper) documents a per-singular-value truncation rule; the code implements a tail-Frobenius rule
`linalg.py:81-82` (signature comments), `:101-106` (Parameters): "removes singular values satisfying sigma < maximum(atol, rtol*sigma1)". Code (`:200-205`) keeps `K = #{i : ||sigma[i:]||_2 >= max(rtol*||A||_F, atol)}`. On `sigma = (1, .08, .08, .08, .08)`, `rtol=0.1` keeps **4** (doc rule: 1); on `sigma=(1,.3,.3)`, `atol=0.35` keeps **2** (doc rule: 1) (`r2_01`). The same comment is copied verbatim into `left_svd`, `right_svd`, `up_svd`, `left/right/up/down_svd_pair` (`:222-223, 265-266, 304-305, 345-346, 391-392, 434-435, 483-484`). The frontend `t3svd` docstrings say "relative tolerance (in Frobenius norm)", which matches the code — only `linalg.py` is wrong. Also `:97-99` lists `min_rank` twice (second should be `max_rank`). Fix: rewrite the comment/Parameters as the Frobenius tail rule ("drop the trailing singular values whose combined Frobenius norm is below max(atol, rtol·‖A‖_F)").

### R2-4 — D, confirmed. `t3_norm(use_orthogonalization=False)` still orthogonalizes (twice)
`t3_linalg.py:232`: the `False` branch calls `t3_inner_product(x, x)` without forwarding the flag, so `t3_left_orthogonalize` runs twice (once per operand), vs once for `True` (`r2_02`: call counts 1 vs 2). `TuckerTensorTrain.norm` (`tucker_tensor_train.py:2378-2381`) promises for `False`: "compute norm with conventional zippering (faster, more suited for automatic differentiation)". Values are identical; the parameter is not honored. Fix: `t3_inner_product(x, x, use_orthogonalization=False)`.

### R2-5 — C, confirmed. `stacking.stack` (hence `TuckerTensorTrain.stack`, `T3Frame.stack`, `T3Tangent.stack_*`) fails under `jit`
`stacking.py:261`: `xnp.moveaxis(stacked, source=xnp.arange(len(axes)), destination=axes)`. Under a jax trace `jnp.arange` is a tracer and `jnp.moveaxis` needs concrete axes → `ConcretizationTypeError` (`r2_14`: `jax.jit(lambda u, v: TuckerTensorTrain.stack((u, v)).data)` fails, eager works; `unstack` works under jit). `test_dispatch` never jits a stack. Fix: `source=tuple(range(len(axes)))`.

### R2-6 — S (under `-O`) / D, confirmed. Structural checks via `assert`: bare `AssertionError` normally, silently wrong or obscure under `python -O`
Demonstrated (`r2_05`, run with and without `-O`): `TuckerTensorTrain.__mul__` (`tucker_tensor_train.py:2023`) — docstring says "Raises ValueError if shapes ... inconsistent"; normally an empty-message `AssertionError`; under `-O`, `x * np.ones((1,5))` and `x * np.ones(5)` on a `(4,5)` T3 **return** a broadcast dense array. `t3_add:61`, `t3_inner_product:195`, `t3_mult:258` (stack mismatch) → empty `AssertionError` / numpy broadcast errors under `-O`; `t3_sum:296-297`, `t3_sum_stack:117` (axis out of range) → `IndexError` under `-O`; `common.xcat/xappend/xprepend:346-396` (`xcat(np.ones(2), [1.0])` → empty `AssertionError`). House rule: structural → hard error always. Fix: convert to `raise ValueError(...)` with messages.

### R2-7 — E, confirmed behaviour (not reachable on supported paths today). `ValueHashedFields` / `ValueHashedMasks` edge cases
(`r2_08`) `ValueHashedFields._value_key` handles only `np.ndarray`: a jax-array field makes `hash()` raise `TypeError: unhashable` and `==` raise "truth value ambiguous" (docstring: "numpy arrays compared by CONTENT" — silent on jax). `ValueHashedMasks`: bool vs int8 masks with equal values are `==` (array_equal) but hash differently (dtype in the hash) — hash/eq contract violation; two holders with different numbers of masks compare equal (`zip` truncation). Also `F(nan) != F(nan)` (identity fast path only), `-0.0`/`0.0` arrays unequal, list vs tuple fields equal. Masks are bool by construction and `SamplingKind.weight` is canonicalized in `__post_init__`, so none of this is reachable from the documented API; worth a guard (`jnp` arrays → `np.asarray` or explicit TypeError) given the mixin's role as the jit cache key.

### R2-8 — E, confirmed. `tree_contains_jax`, `tree_to_jax`, `stacking.tree_depth` recurse forever on a `str`
A `str` is a `typ.Sequence` whose `[0]` is itself a `str`: `tree_contains_jax((np.ones(2), 'left'))` → `RecursionError`; `tree_to_jax((np.ones(2), 'ab'))` returns the repr of a generator as the second leaf (`r2_12`, `r2_07`). No library call site puts strings in data trees (checked), so E.

### R2-9 — E, confirmed correct. `t3_right_orthogonalize` and the single-core SVD steps are correct but untested
(`r2_04`) `t3_right_orthogonalize` preserves the tensor (relerr ≤ 3e-15) and yields `t3_orthogonality_residual(side='right') ≤ 1.3e-15` on 4 structures × 3 stacks, incl. unsquashed tails — the mirrored contract of `t3_left_orthogonalize` holds. Same sweep passes for `t3_orthogonalize_relative_to_{tucker,tt}_core` (every `ii`: tensor preserved; all cores except the named one orthogonal in the expected direction), `t3_{down_svd_tucker,left_svd_tt,right_svd_tt,down_svd_tt,up_svd_tt}_core` (every `ii`, incl. the boundary branches), and `t3_up_orthogonalize_tt_cores`. None has a direct test; the map's "dead or untested promise" flag is resolved as "untested, correct".

### R2-10 — D, confirmed (minor comment/docstring errors in scope)
- `linalg.py:349,395` `left/right_svd_pair` return comment `new_G1 shape=(..., r, nb, nj)` → should be `nk`.
- `linalg.py:263-264, 302-303, 432-433, 481-482`: rank bound `minimum(ni*na, nj)` copied into `right_svd` (should be `min(ni, na*nj)`), `up_svd`/`up_svd_pair` (`min(ni*nj, na)`), `down_svd_pair` (`min(na, N)`).
- `linalg.py:262,268-270,301,307-309`: `right_svd`/`up_svd` shape comments omit the leading `...` stack both support (verified on stacks).
- `t3_operations.py:184` `tucker_change_core_shapes` docstring "for TT cores" (copy of the tt version).
- `t3_orthogonalization.py:347` `t3_up_svd_tt_core` docstring says "right unfolding" (it is the up unfolding); `:294` duplicated assignment `new_tt_cores[ii] = new_tt_cores[ii] = ...`; `:250` local named `U_i_a_x` has axes `(a,i,x)`.
- `stacking.py:488` `basic_uniform_stack` docstring "into single ragged array tuple".
- `t3_orthogonalization.py:225` `t3_left_svd_tt_core` docstring does not mention the `ii == d-1` branch, which sums the trailing bond with ones (a squash) and returns the squashed core's singular values.

### R2-11 — E, related_known. jax-absent behaviour (characterized)
(`r2_11`, jax import blocked) `get_backend(*, use_jax=True)`, `common.randn(use_jax=True)`, `TuckerTensorTrain.randn/zeros(use_jax=True)`, `t3_corewise_randn(use_jax=True)`, `tree_to_jax` all raise `NameError: name 'jnp' is not defined`; `common.to_jax` silently returns a numpy array. Broader than the HANDOFF "Small" entry (which names only `get_backend`) — the constructors are the user-facing surface that hits it.

### R2-12 — E, confirmed. `stacking` edge cases on malformed trees
(`r2_07`) `tree_zip` silently truncates on unequal lengths; `stack` silently ignores extra leaves in non-template elements (structure is taken from `T[0]...[0]` only); `unstack` normalizes negative axes against the *first* leaf's ndim, so on leaves of different ndim a negative axis slices a different axis on the other leaves (A(4,2,3),B(2,3), axes=(-2,) → B sliced along its axis 1); `tree_depth(())`, `get_first_leaf(())` → `IndexError`; `apply_func_to_leaf_subtrees` with a leaf that does not match the template → `TypeError: 'int' object is not iterable`. All on unsupported inputs; the doc (§1) describes the happy path only.

### R2-13 — E, confirmed. Minor backend-only ergonomics
`t3_linalg.py:179`: `t3_inner_product` infers jax-ness with `x[0] + x[1] + y[0] + y[1]` → `TypeError` if a raw-`.data` user mixes a list family with a tuple family (every other op uses `tree_contains_jax`). `t3_operations.py:287`: `t3_sum(axis=np.array([0,1]))` → "truth value ambiguous" (an ndarray is not a `typ.Sequence`). `linalg.truncated_svd`: a zero matrix with `rtol` keeps full rank (tol = 0); `min_rank` larger than `min(N,M)` silently returns fewer; `min_rank > max_rank` → `min_rank` wins (comment says `min_rank <= max_rank` is required, nothing checks). `common.save/load_core_families` drops a trailing empty family on load (unreachable: every family has `d >= 1` cores).
