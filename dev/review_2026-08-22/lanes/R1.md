# Lane R1 — TuckerTensorTrain frontend (`t3toolbox/tucker_tensor_train.py`)

Scope: `TuckerTensorTrain` (all ~110 methods), `T3Weights`, `t3_absorb_weights`, `t3_weighted_norm`,
`t3_weighted_inner`; the backend signatures they delegate to; doc pages `docs/t3svd_minimal_ranks.md`,
`docs/t3m_methods.md`, `docs/rank_continuation.md`, `README.md` quickstart (run by hand),
`docs/getting_started.rst`.

Repro scripts: `scratchpad/repros/R1/` — `sigs.py` (signature extraction), `batch1.py`, `batch2.py`,
`batch2b.py`, `batch2c.py`, `batch3.py`, `weights_reverse.py`, `t3m_tails.py`, `t3m_tails2.py`,
`t3m_tails3.py`, `readme_fences.py`.

## What was checked and how

1. **Delegate argument order** — extracted every delegated backend signature with `ast` (`sigs.py`) and
   compared against each frontend call. All 60-odd delegate calls pass arguments in the callee's order
   (`probing.t3_probe(ww, data)`, `t3_probe_corewise_transpose(ztildes, ww, data)`, the derivative
   transposes `(c/ztildes, ww/index, pp, data, order)`, `compute_continuation_ranks(shape, ss_tucker,
   ss_tt, ...)`, `corewise_stack_sum(data, axis, n_stack)`, `basic_ragged_unstack(data, 1)` etc.). No
   mismatch found. Note: the frontend does not expose `chunk_size` on
   `probe_corewise_derivatives_transpose` (backend default 100) — consistent with the HANDOFF backlog.
2. **Docstrings / shape comments vs bodies** — read the whole file. Findings below (R1-5…R1-8, R1-10).
3. **Doc pages** — the three scope pages read claim by claim; `rank_continuation.md` and
   `t3svd_minimal_ranks.md` doctested blocks are consistent; one non-doctested snippet is wrong (R1-9);
   `t3m_methods.md` claim "boundary bonds stay 1" is false for two methods (R1-10). README python fences
   run by hand (`readme_fences.py`): outputs match the comments exactly (`(5, 6, 5) (2, 4, 4, 2)`,
   `0.0`, `(4, 6, 4) (1, 4, 4, 1)`, fit rel err 1.8e-12).
4. **Weakly-tested names** — `from_tensor_train`/`to_tensor_train` (stacked, r0≠1: dense error ~1e-14,
   exact round trip), `sum_stack_corewise`, `orthogonalize_relative_to_{tucker,tt}_core`,
   `up_orthogonalize_tt_cores`, `down_orthogonalize_tucker_cores`, `left/right_orthogonalize_tt_cores`
   verified at an asymmetric d=4 structure `(5,7,4,6)/(3,4,2,3)/(2,3,4,2,3)` with stacks `(), (2,), (2,3)`:
   represented tensor unchanged and the documented orthogonality (complement-orthogonality of the kept
   core, left/right/up orthogonality of the subtrees) all hold to 1e-10 (`batch3.py`). `get_core_shapes`
   vs `core_shapes` — consistent with the (known) inconsistency in the HANDOFF backlog.
5. **Sharing at asymmetric shapes** (`batch2.py` §M): shape `(5,7,5,6)`, non-adjacent group
   `sharing=(0,1,0,2)`, distinct ranks, stacked and unstacked: `t3svd` lossless (1.4e-15), tied output,
   equal group spectra, left-orthogonal; truncated grouped sweep tied; `rank_adjustment_sweep(sharing=)`
   lossless + minimal under the group ceiling; `share` from untied input tied at the expected ranks;
   `resize(sharing=)` grows/shrinks tied and lossless, raises on untied in safe mode;
   `continuation_ranks(sharing=)` with/without `max_grow`; bad specs (length, unequal sizes, unequal caps)
   all raise clear ValueErrors. No defects.
6. **Operators** (`batch1.py`): `+`, `-`, `*`, `-x`, scalar, ndarray, stacked; `inner`/`norm`/`sum`
   semantics vs dense — correct. Asymmetries/raise-type mismatches recorded (R1-4, R1-5, R1-12, R1-13).
7. **save/load** with stacks, jax-backed input, `use_jax=True`, open file handle — round-trips exactly.
8. **T3Weights** (`batch2c.py`, `weights_reverse.py`): `from_t3svd` consistent on a minimal-rank point;
   `t3_weighted_norm == absorb().norm()`, `t3_weighted_inner == inner of absorbed`; `reverse` consistent
   with `TuckerTensorTrain.reverse` against a hand-built dense reference (diag weights on every edge,
   1e-14); `stack`/`unstack` round-trip; `concatenate`↔`+` and `kronecker`↔`*` absorb identities hold;
   jax `sqrt`/`reciprocal`/weighted norm work.
9. **jax / jit** (`batch3.py`): copy, reverse, squash_tails, resize, segment, concatenate, sum_stack,
   sum_stack_corewise, sum, arithmetic, inner, norm, t3svd, orthogonalizations, from/to tensor train,
   to/from vector all jax-preserving; under `jax.jit`: resize, reverse, sum_stack, segment, squash_tails,
   from_canonical, from_tensor_train, t3m (inplace/swap), rank_adjustment_sweep, sum(axis), `x+s`, copy,
   to_dense all trace. `T3.stack(x.unstack())` under jit does not (R1-17).
10. **d=1 and non-1 boundary bonds** — all core ops fine at d=1. With **non-1 boundary TT bonds**
    (`r0, rd ≠ 1`, explicitly allowed by the class docstring): `t3svd`, `rank_adjustment_sweep`,
    `continuation_ranks`, `share`, `norm`, `inner`, `sum`, `sum_stack`, `+`, `probe`, `entries`, `x*y`
    (no truncation, all three `t3m` methods) are all correct. **Truncating `t3m` is not** (R1-1, R1-2).

## Findings

### R1-1 (S, confirmed) `t3m(method='inplace_fused')` ignores `max_tt_ranks` on the last bond when `rd ≠ 1`
`backend/t3_linalg.py:337` (body of `t3m_inplace_fused`; the frontend is `tucker_tensor_train.py:2032`).
`t3svd`, `t3_inner_product`, `t3_norm` and `t3m_form_then_round` (via `t3svd`) squash the boundary
bonds first; `t3m_inplace_fused` does not, so the product's right boundary bond `rd = rd_x·rd_y`
survives untouched and uncapped. `t3m_tails2.py`: x `tt_ranks=(2,2,2,3)`, y `(3,3,2,2)`, shape `(5,6,7)`:

```
max_tt=3,max_tk=3   form_then_round  ranks ((3,3,3),(1,3,3,1))  caps honored  relerr 3.43e-02
max_tt=3,max_tk=3   inplace_fused    ranks ((3,3,3),(1,3,3,6))  tt cap NOT honored  relerr 1.17e-01
max_tt=(1,3,3,1)    inplace_fused    ranks ((5,6,4),(1,3,3,6))  tt cap NOT honored  relerr 8.41e-02
```
(same with `stack_shape=(2,)`, relerr 3.4e-01 vs 5.4e-02; under jit on a `(2,2,2,3)` operand squared
with cap 3 the result reported `tt_ranks=(1,3,3,9)`.) The left bond IS squashed (`(1,…)`), so the
output is asymmetric. Supported: class docstring says `r0, rd ≠ 1` is allowed; `t3m` docstring promises
"a scalar caps every position" and names no tails precondition. Fix: `tt_squash_tails` both operands at
the top of `t3m_inplace_fused` (as `t3_inner_product` does at `:183`), or cap/squash the final bond.

### R1-2 (C, confirmed) `t3m(method='swap')` crashes / mis-structures with non-1 boundary bonds
`backend/t3_linalg.py:536`. When both operands have `rd ≠ 1`: `ValueError: operands could not be
broadcast together ...` from `_t3m_contract_pair` (`:456`), for every truncation spec (`t3m_tails2.py`,
`t3m_tails3.py`). When boundary bonds are non-1 on the left, no crash but the boundary bond migrates to
the other side and quality collapses: inputs `r0=(2,3), rd=1` → output `tt_ranks=(2,3,3,3)` (an `rd=3`
from nowhere), relerr 6.8e-01 vs 1.3e-01 (`form_then_round`); `y r0=3 only` → `(1,3,3,3)`. Same
root cause as R1-1 (no `tt_squash_tails`); the same fix applies. Also contradicts
`docs/t3m_methods.md:56` ("the boundary bonds stay 1").

### R1-3 (C, confirmed) `entries` with a wrong-length *list* index raises `AttributeError`
`tucker_tensor_train.py:3380`: the ValueError message is built with `index.shape[0]`, but `index` is
documented as "array or convertible"; `x.entries([1,2])` on d=3 → `AttributeError: 'list' object has no
attribute 'shape'` (`batch1.py` §A). Fix: use `len(index)`.

### R1-4 (D/C, confirmed) `__mul__` with a wrong-shape ndarray: bare `assert`, docstring says `ValueError`
`tucker_tensor_train.py:2023` `assert(other.shape == self.stack_shape + self.shape)`. `x * randn(5,6)` →
`AssertionError:` with no message; stripped under `python -O` (then falls into numpy broadcasting).
Docstring "Raises ValueError" (`:1974`). House rule: structural → hard error. Fix: raise ValueError like
`__add__` does.

### R1-5 (D, confirmed) `__add__`/`inner` raise `NotImplementedError` on stack-shape mismatch; docstrings say `ValueError`
`tucker_tensor_train.py:1857` (doc) vs `:1909` (code); `:2175` (doc) vs `:2303` (code). `batch1.py` §D.
Either change the raise to ValueError (it is a structural inconsistency) or document the actual type.

### R1-6 (D, confirmed) `reverse` docstring claims `tt_ranks=(1, r(d-1), ..., r1, 1)`
`tucker_tensor_train.py:1090`. Code reverses the full tuple: `(rd, r(d-1), ..., r0)`; for input
`(2,2,3,4)` it returns `(4,3,2,2)` (`batch1.py` §G) — and the method's own doctest prints `(4,3,2,1)`.

### R1-7 (D, confirmed) `probe` shape comment/prose drop the frame stack `C` and use an undefined letter `X`
`tucker_tensor_train.py:3483` return comment `elm_shape=X+W+(Ni,)`; prose `:3495-3497` says
`elm_shape=W+(Ni,)`. Actual (and the doctest at `:3522`) is frame-inner `W + C + (Ni,)` — e.g.
`(4,5,1, 2,3, 14)`. `probe_ambient_transpose` `:3557` has it right. Map candidate: confirmed.

### R1-8 (D, confirmed by reading) docstring notation errors in the class/method docs
- `:101` `tucker_ranks = (n0, r1, ..., n(d-1))` → `(n0, n1, ..., n(d-1))` (map candidate: confirmed).
- `:195-198` minimal-rank conditions "for `i=1,...,d`" on 0-indexed `ri/ni/Ni` (should be `0..d-1`;
  also `r(i+1)` at `i=d` is undefined) (map candidate: confirmed).
- `:63-71` diagram labels the last core `nd`/`Nd` (should be `n(d-1)`/`N(d-1)`; same slip as the known
  README `B0…Bd` item).
- `:624` `get_minimal_ranks`: "`Ni x (N1*...*N(i-1)*...)`" → `N0*...`.
- `:1461-1463` `randn`: `tucker_ranks`/`tt_ranks` described as optional with `None` defaults; they are
  required positionals (copy-paste from `zeros`).
- `:2434` `sum`: "For corewise norm, see `corewise_norm`" → `corewise_sum`; `:2450-2452` axes "1,dots,d".
- `:2664`, `:2736`, `:2807`, `:2878` all four `*_svd_*_core` say "index of TT core to SVD" (`down_svd_tucker_core`
  is a Tucker core); `:2686` `ss[ii].shape = new_x.stack_shape + new_x.tucker_ranks[ii]` (missing tuple).
- `:2873` `up_svd_tt_core` summary says "right unfolding" (it is the up/down unfolding); `:2905` its
  See-Also lists itself and omits `right_svd_tt_core`.
- `:3294`/`:3409` "base-inner" — the library term is "frame-inner" (map candidate: confirmed, trivial).

### R1-9 (D, confirmed) `docs/rank_continuation.md:179` calls `resize` with the wrong arity
Uniform-layer loop snippet: `x = x.resize(new_tucker, new_tt)`; `resize(new_shape, new_tucker_ranks,
new_tt_ranks)` requires the shape first (every other snippet and `examples/fit_hilbert_uniform_newton_cg.py:145`
pass it). Plain fence, not doctested, so CI cannot catch it.

### R1-10 (D, confirmed) `docs/t3m_methods.md:56` "the boundary bonds stay 1"
False for `inplace_fused` (`rd` stays `rd_x·rd_y`) and `swap` (crash / migrated bond) — see R1-1/R1-2.
True for `form_then_round` only.

### R1-11 (C, confirmed) `sum_stack(axis=<out of range>)` → bare `AssertionError`
`backend/t3_linalg.py:117` `assert(0 <= ax < m)`; `xs.sum_stack(axis=5)` on `stack_shape=(2,)`
(`batch3.py`). Structural → should be a ValueError.

### R1-12 (E, confirmed) no `__rmul__`/`__radd__`/`__truediv__` on `TuckerTensorTrain`
`2.0 * x`, `np.float64(2) * x`, `2.0 + x`, `x / 2.0` all `TypeError` (`batch1.py` §B), while
`UniformTuckerTensorTrain` defines `__rmul__ = __mul__` (`uniform_tucker_tensor_train.py:250`) and
`T3Tangent` supports `0.1 * v` (`getting_started.rst:82`). No doc promises it for the ragged T3, so E.

### R1-13 (E, confirmed) `TuckerTensorTrain`/`T3Weights` are `eq=True` dataclasses over arrays
`x == y` on two equal-valued T3s raises `ValueError: The truth value of an array ... is ambiguous`;
`hash(x)` → `TypeError: unhashable`; `x == x` is `True` only via identity (`batch1.py` §E). `T3Frame`
is `eq=False`. No doc promises equality; worth a deliberate decision (`eq=False`, or a value `__eq__`).
Map candidate: confirmed.

### R1-14 (C minor, confirmed) `share(..., rtol=)` on a stacked T3 fails deep in `truncated_svd`
`tucker_tensor_train.py:4264`: `t3svd`/`t3m`/`t3svd_dense`/`continuation_ranks` all check
"stacked + rtol/atol" at the frontend with a T3-level message; `share` does not, so the error is
"Cannot use truncated_svd with rtol or atol for stacked matrix A (len(A.shape) > 2)" (`batch1.py` §F).

### R1-15 (E, confirmed) `t3_absorb_weights` with shape-inconsistent weights fails inside einsum
`tucker_tensor_train.py:4793`: `t3_absorb_weights(x, W2)` with mismatched ranks → einsum "operands could
not be broadcast" rather than a structural ValueError; `is_consistent_with` exists but is not used
(`batch2c.py`). Also the easy way to get there is `T3Weights.from_t3svd(x)` on a non-minimal `x`
(known backlog item).

### R1-16 (D/E, confirmed) `has_numerically_minimal_ranks` on a structurally-minimal stacked T3 raises
`tucker_tensor_train.py:721`: returns `False` early when not structurally minimal, but on a minimal
stacked point it calls `t3svd(rtol=...)` and raises the stacked-rtol ValueError; docstring promises a
bool and does not mention the restriction (its siblings `is_left_orthogonal` etc. are per-stack-element).

### R1-17 (E, confirmed, root cause not analysed) `T3.stack(x.unstack())` does not trace under `jax.jit`
`ConcretizationTypeError: ... traced array with shape int32[1] expected a static index` (`batch3.py`).
Not promised anywhere; every other method tried traces fine.
