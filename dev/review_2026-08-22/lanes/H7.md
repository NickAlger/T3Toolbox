# Lane H7 — docs versus code (prose contradicting the code)

Scope: every page in `docs/*.md`, `docs/contributor/*.md`, `docs/*.rst`, `README.md`, `CHANGELOG.md`,
`docs/release_notes.md`, `CLAUDE.md`, `CITATION.cff`, `pyproject.toml`, and the module docstrings of
`t3toolbox/*.py` + `t3toolbox/backend/*.py`. Repro scripts + captured outputs: `scratchpad/repros/H7/*.py|*.out`.

## Method

1. **Mechanical scans** (scripts in `repros/H7/`):
   - `api_ref_check.py` — every `:py:class/func/mod:` target in `api_reference.rst` resolves by import; every
     name in the frontend section is actually at the package root; root `__all__` vs the page; every
     backend module and every frontend module named on the page; each frontend module's `__all__` vs root.
   - `changelog_symbols.py` — every symbol / signature / default the CHANGELOG (2026.2.0, 2026.1.0) and
     `release_notes.md` claim (new names, removed names, `from_point`, `with_sharing`, `has_block_sumsq`,
     `Geometry` protocol members, `_cg_solve`, `NewtonInfo.g0norm`, `cg_forcing_power=0.5`,
     `chunk_size=100`, the jet names and `_trs` twins, `prefix_mask`/`require_concrete_masks`, `use_jit`
     keyword on the three optimizers, `val_sample`/`val_data`/`callback`, `probe_model(weight=)`, the
     `backend.sharing` surface, `t3_share_tucker_factors`, `uniform_minimal`, `shared_data=` threading).
   - `path_check.py` — every repo path (`docs/…`, `dev/…`, `examples/…`, `backend/…`) mentioned in all the
     above files and in every module docstring exists; every relative markdown link in `docs/**` resolves.
   - `claude_md_idents.py` / `docs_idents.py` — every backticked identifier in `CLAUDE.md` and in all docs
     pages is grepped (whole word) against `t3toolbox/`, `tests/`, `examples/`; survivors reviewed by hand.
   - `readme_fences.py` — the three README python fences run by hand; printed values vs the comments.
   - stale-word grep (`slice|deferred|parked|TODO|later|3b|5b|dev/`) over every module docstring (AST).
2. **Behavioural checks** of prose claims: `numerical_contracts_check.py` exercises every row of
   `docs/numerical_contracts.md` (raises vs no-check) with a genuinely non-orthogonal frame, an ungauged
   tangent, a foreign-frame tangent, an untied shared point; `user_guide_claims*.py`/`gd_stacked.py` check
   core/supercore/mask shapes, `transport`, `sum_stack_corewise`, `contractions.__all__`, the
   `sum_over_probes` default, the stacked-`x0` `NotImplementedError` on all four optimizers, the uniform
   non-minimal `x0` path; `fitting_doc_claims.py` checks `LocalModel` members, the nine `SamplingKind`
   members, the stacked+regularizer raise on the factory, the non-field-parameter `TypeError`, and the
   `random_orthogonal` slack example from `frame_variations.md`.
3. Defaults named in prose (`grep -i default` over user docs) compared against `inspect.signature`.
4. Paper-section references compared against the local `t4s.txt` section/algorithm index.

## Findings

### D — doc ≠ code (confirmed)

**H7-1  `docs/numerical_contracts.md:86` says `shared(…).frame(x)` has a TIED precondition; the code ties
silently.** Row: "`shared(…)` wrapper: `frame(x)`, `transport(v, new_frame)` | **TIED** (the point / the new
frame)". CHANGELOG 2026.1.0 (`CHANGELOG.md:159-162`) documents the opposite — "`shared(...).frame(x)` ties an
untied `x` first, silently, by the per-group mean" — and the code does exactly that:
`shared_manifold((0,0,1)).frame(x_untied)` → no raise (`numerical_contracts_check.py`:
`shared.frame untied ... -> no raise`), while `transport` to an untied frame does raise. Fix: split the row —
`frame(x)`: "— (ties the point first; untied input is silently projected)", `transport`: TIED (new frame).

**H7-2  `docs/user_guide.rst:388` — "The probing algorithms are described in Section 5 of our paper [1]."**
In the local `t4s.pdf` (the numbering CLAUDE.md says to cite) §4 is "Derivative probing", §5 is "Fitting the
model", and the T3 probing algorithms (Algorithms 5–8) are in §6 "Riemannian Jacobian" (`t4s.txt:798, 1200,
1820, 1941-2071`). `docs/entries_apply_probe.md:35,231` correctly say Section 6. Fix: "Sections 4 and 6".

**H7-3  `docs/user_guide.rst:37` — "Tucker ranks: (n0, r1, ..., n(d-1))"** — `r1` should be `n1`.

**H7-4  `docs/user_guide.rst:139-147` — frame/variation families listed as `(U0,...,Ud)`, `(L0,...Ld)`,
`(R0,...,Rd)`, `(O0,...,Od)`, `(V0,...,Vd)`, `(H0,...,Hd)`** — every family has `d` cores (`0..d-1`); the
tangent diagram just above uses `U0 U1 U2` for `d=3`. Same off-by-one class as the known README/user-guide
`B0…Bd` item but in a second place (the manifold section), and the field is called `tucker_cores` where the
class field is `up_tucker_cores` (`frame_variations_format.py:239-245`). Broader than the known item.

**H7-5  `t3toolbox/backend/ut3_orthogonalization.py:137` (rendered docstring of
`up_orthogonalize_tt_supercores`) cites "the orthogonal-representation sweep
(`backend/orthogonal_representations.py`)"** — no such module exists; the sweep that reuses this SVD core is
`backend/fv_conversions.py:173-174` (`uniform_orth.up_orthogonalize_tt_supercores`). `path_check.py`:
`t3toolbox/backend/ut3_orthogonalization.py:137: MISSING backend/orthogonal_representations.py`.

**H7-6  `CLAUDE.md:455` names "the (breaking) `GeometryOps.precompute` aux slot" as part of the SF-T3
surface; `GeometryOps` was removed in 2026.2.0** (`CHANGELOG.md:17`; the protocol is now `Geometry` in
`backend/optimizers.py:59` and the classes are `backend.geometry.*GeometryOps`). `CLAUDE.md:448-449` also
still says SF-T3 is "slices 0–7 pushed, 8–13 local pending review" although it shipped in 2026.1.0
(`CHANGELOG.md:67-71`), and `CLAUDE.md:469` still frames the facade as "Deferred to 1.1; 1.0 ships" in the
pre-calendar version scheme. Broader than the known "Current-state says UNRELEASED" item.

**H7-7  `docs/getting_started.rst:4` — "a tour of the frontend in five short examples"** — the page has six
sections (Create / Sample / Tangents / Fit / Shared Tucker factors / NumPy or JAX; headers at lines 8, 34, 61,
88, 115, 144). Trivial.
