## Findings

### H1-1 (C, confirmed) numpy-integer `shape` entries on a uniform point crash `newton_cg(use_jit=True)` deep inside
`common._is_static_leaf` (backend/common.py:608) treats only Python `int`/`bool` as static. A
`UniformTuckerTensorTrain` whose `shape` is `tuple(np.int64(...))` (e.g. `tuple(np.array(shape))`) constructs, validates,
and `jax.jit(lambda u: u.norm())` works (the frontend aux is hashable), but the backend `partition_static` of the frame
tuple turns those shape entries into *traced leaves* (repro: 7 dynamic leaves vs 4), and `_jitted(_cg_core)` dies with
`TracerArrayConversionError: ... __array__() was called on traced array with shape int32[]`. A numpy-array `shape` fails
even at `jit(norm)` with jax's "Exception raised while checking equality of metadata fields". Eager runs are fine.
Library constructors already canonicalize (`ut3_constructors.py:103 tuple(int(Ni) ...)`); the dataclass constructor does
not. Fix: canonicalize `shape` to Python ints in `UniformTuckerTensorTrain`/`UT3Frame`/`UT3Variations` validation, and/or
accept `np.integer`/`np.bool_` scalars in `_is_static_leaf`.

### H1-2 (C, confirmed) jax-array masks are accepted by the holders but cannot be a cache key
`UT3Masks(jnp bool arrays)` passes `validate()` (`is_boolean_ndarray` accepts jax; `require_concrete_masks` only rejects
tracers); `to_jax()` correctly keeps masks numpy; eager `newton_cg` works. But `UniformManifoldGeometryOps.from_point`
/ `Uniform*Kind.from_point` store the jax arrays in value-hashed fields and `ValueHashedFields._value_key` (common.py:541)
handles only `np.ndarray` → `TypeError: unhashable type: 'jaxlib._jax.ArrayImpl'`; `newton_cg(use_jit=True)` surfaces as
jax's obscure "Exception raised while checking equality of metadata fields of pytree". (`ValueHashedMasks` happens to work
because jax arrays have `tobytes`.) Masks are documented HOST numpy, so this is an unsupported input with an unhelpful
error, not a wrong answer. Fix: require `isinstance(m, np.ndarray)` in the three holders' validation (reuse the
`require_concrete_masks` wording), or `np.asarray` in `__post_init__`.

### H1-3 (D, confirmed) "all instances of a geometry are interchangeable" (manifold.py:1532-1534) is false
A pytree round-trip of `MANIFOLD` yields a fresh `ManifoldGeometry()` (`is MANIFOLD` False, `==` False). `fitting.apply_model`,
`shared_geometry.SharedGeometry(...)` and `optimizers._geometry_ops` all reject it with ValueError (identity checks).
Only the geometry's own methods still work. Fix: unflatten to the singleton (`lambda aux, ch: MANIFOLD`) — makes the
comment true at zero cost — or give the frontend geometries value eq and relax the `is` checks.

### H1-4 (D, confirmed) stale "T3Frame as jax aux" comments
`frame_variations_format.py:40-41`: "eq=False -> identity __hash__/__eq__, so a T3Frame can be jax aux_data". `T3Frame`
is never aux: it is a child of `T3Tangent` (manifold.py:1526) and of `GaussNewtonModel` (fitting.py:688).
`docs/contributor/uniform_pytree_composition.md:152-160`: heading "Why `T3Frame` (jax arrays) is fine as aux" and bullet
"`T3Frame` is aux used only as data", with a parenthetical conceding it "actually flows as a pytree leaf". Fix: reword to
"leaf"; the eq=False on T3Frame is then justified by "holds arrays" alone.

### H1-5 (E, mechanism confirmed, no supported path) value key is cached; aliased, writeable mask arrays
`ValueHashedFields._fields_key` is a `cached_property`. `Uniform*GeometryOps.from_point` / `_UniformKind.from_point` store
`tuple(base_masks)` — the *same* writeable arrays as `x0.masks.data`. Mutating them after the first hash leaves the key
stale: repro shows hash unchanged, `== fresh(original content)` True, `== fresh(mutated content)` False. `_weight_matrix`
already defends its array (copy + `setflags(write=False)`); the masks don't. No library code writes masks in place (grep),
so only user in-place mutation reaches it. Fix: copy + `setflags(write=False)` in `from_point` or in the holders.

### H1-6 (E, confirmed) `ValueHashedMasks` eq/hash contract: bool vs int8 same content → `==` True, hashes differ
`np.array_equal` ignores dtype, the hash includes it. Harmless (a cache miss), and `UniformTuckerTensorTrain.validate`
rejects non-bool masks, so it only affects a bare holder. Fix: include dtype in `__eq__`.

## Not a finding (checked)
- `IdentityRegularizer` with float / np.float64 / np.float32 / 0-d np.array / jax scalar strength: all run under
  `use_jit=True` with identical objectives (jax handles 0-d aux).
- `SharedGeometry` subclass as a *direct* jit argument is a leaf → TypeError (unregistered subclass; expected, it works as aux).
- `weight` aliasing: `_weight_matrix` copies and freezes (the shipped bug stays fixed).
- `jax_map` weak adapter: bound methods of value-equal kinds would share an adapter only while the key is alive, and then
  compute with an equal-valued kind — no divergence possible beyond what `__eq__` already guarantees.
- `_wchunked_sum_step` / `_assembly_per_row_bytes` keys are complete and hashable (tuples, ints, `np.dtype`).

## Not checked
`UT3Weights`/`UT3FrameWeights` under `vmap` with varying masks; persistent compilation cache; multi-device sharding keys;
the `_pairwise_path`/`_expanded_subscripts` caches (pure string keys — trivially sound).
