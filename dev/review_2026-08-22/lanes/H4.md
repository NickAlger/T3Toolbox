# Lane H4 — dispatch, jit, and edge structures (hunter lane)

Repo `/home/nick/repos/T3Toolbox` @ `657f6001`, read-only. All scripts under
`scratchpad/repros/H4/` (paths below are relative to that directory). Python
`/home/nick/miniconda3/envs/t3toolbox/bin/python`, jax 0.10, `jax_enable_x64` ON for every

## Method

1. **Op matrix, ragged** (`matrix_ragged.py`, outputs `matrix_ragged_t3.out`, `matrix_ragged_tangent.out`):
   58 `TuckerTensorTrain` ops + 52 frame/tangent/geometry/weights ops, each run on (i) numpy, (ii) jax eager,
   (iii) `jax.jit` for the ops documented/expected jittable (fixed-shape ops), over 9 asymmetric edge structures
   × stack shapes `()`, `(1,)`, `(2,)`:
   `d1 (5,)/(2,)/(1,1)`, `d1_square (3,)/(3,)/(1,1)`, `d2 (4,6)/(2,3)/(1,2,1)`, `d2_rank1`, `d3_rank1`,
   `d3_mode1 (1,5,6)/(1,2,3)/(1,2,2,1)`, `d3_square (3,4,5)/(3,4,5)/(1,2,3,1)`,
   `d3_nonmin (4,5,6)/(2,2,2)/(1,4,4,1)` (TT rank above the product bound), `d4 (3,4,5,2)/(2,3,2,2)/(1,2,3,2,1)`.
   Comparison is on **invariants** (dense tensors, scalars, coordinate tuples where the frame is the same input),
   plus a jax-in→numpy-out leak check on every jax result. (jit was run on 4 structures × 2 stacks to fit the time box.)
2. **Op matrix, uniform** (`matrix_uniform.py` → `matrix_uniform.out`): 70 uniform ops incl. the whole uniform
   weighted layer, same three backends, plus a **uniform-vs-ragged value check** for 30 ops. Supercore-leak check
   (masks numpy = by design, not flagged).
3. **Fitting sweep** (`fit_edge_jit.py` → `fit_edge_jit.out`): `newton_cg` numpy vs `use_jit=True` (x64) for all
   6 kinds × {MANIFOLD, COREWISE, UNIFORM_MANIFOLD} × 5 edge structures, comparing objective histories.
4. **jax absent** (`jax_absent.py`, `jax_absent_optim.py`): `sys.modules['jax']=None`, exercising the numpy paths
   (ragged + uniform + manifold + optimizers + weights + save/load).
5. **python -O** (`asserts_under_O.py`): the 29 `assert(...)` sites enumerated by grep; structural-error cases run
   with and without `-O`.
6. **float32 / tolerance** (`f32_safe_mode.py`, `gauge_tol_scaling.py`, `mixed_and_float32.py`): safe-mode checks on
   jax default float32, mixed numpy/jax operands, large-magnitude numpy data.
7. Targeted follow-ups: `uniform_orth_reps_rankdef.py`, `uniform_stacked_frame.py`, `uniform_rankdef_frame.py`,
   `uniform_rankdef_apples.py`, `uniform_resized_x0_fit.py`.

## Findings

### H4-1 (C, confirmed) — safe-mode GAUGE check applies the *relative* tolerance as an *absolute* bound on the max-abs gauge residual → false failures for large tangents and for jax-float32
`t3toolbox/manifold.py:1295-1301` (`inner`), `:1314-1319` (`norm`), same pattern in `uniform_manifold.py`.
`safety.effective_rtol` (doc: "rtol", `DEFAULT_RTOL_NUMPY=1e-9`, `DEFAULT_RTOL_JAX=1e-5`) is passed as
`atol=` to `T3Tangent.is_gauged`, which tests `gauge_residual <= atol` where `gauge_residual` is the
**unnormalized** max-abs of `UᵀV` / `LᵀH` — it scales linearly with the tangent's magnitude.
- `gauge_tol_scaling.py`: numpy float64, `p = MANIFOLD.project(v * s)`: s=1e4 → residual 2.2e-10 OK; s=1e6 →
  `|p| = 5.4e7`, residual 1.5e-8 > 1e-9 → `MANIFOLD.norm(p)` / `MANIFOLD.inner(p,p)` raise
  "requires gauged variations" on a tangent the library itself just gauged.
- `f32_safe_mode.py` (jax default float32, the "jax-but-not-jit usage in safe mode (autodiff prototyping)" the
  project guide says the two tolerances exist to support): `MANIFOLD.norm(MANIFOLD.project(T3Tangent(*t3_orthogonal_representations(x.to_jax()))))`
  raises for a plain `randn((4,5,6),(2,3,2),(1,2,2,1))` (|p|≈54, residual 1.2e-5 > 1e-5) and for
  `(6,7,8,5)` (residual 7.3e-4). The uniform twin (`UNIFORM_MANIFOLD.norm`) fails identically. With x64 everything passes.
  `T3Frame.is_orthogonal` is fine (orthonormal cores have O(1) scale), so the ORTH check does not have this problem.
Fix: make the gauge residual relative (divide by the corewise norms of the paired cores, or compare against
`rtol * |V|·|U|`), or document the tolerance as absolute and pick it per dtype. Also `is_gauged(atol=1e-9)` default.

### H4-2 (S in unsafe/jit, C in safe mode; confirmed) — uniform orthogonal frame is NOT orthogonal for numerically rank-deficient trains (zero-padded `resize` warm starts, `x + x`), ragged twin is
`t3toolbox/backend/ufv_conversions.py:60` (`ut3_orthogonal_representations`, also behind `UT3Frame.from_ut3`
`uniform_frame_variations_format.py:296` and `UNIFORM_MANIFOLD.frame`).
- `uniform_rankdef_frame.py`: `x = randn((6,7,8),(2,2,2),(1,2,2,1)).resize((6,7,8),(3,3,3),(1,3,3,1))`
  (structurally minimal, `has_minimal_ranks=True`, exactly the warm start of the documented uniform rank-continuation
  loop, `docs/rank_continuation.md:161-180` and `examples/fit_hilbert_uniform_newton_cg.py`):
  ragged frame residual 6.7e-16; **uniform frame residual 1.0**. `UNIFORM_MANIFOLD.project_ambient` raises
  "requires an orthogonal frame" in safe mode; in unsafe mode the Riemannian gradient differs from the ragged one by 36%.
  Also `y2 + y2` with `(8,9,10),(2,3,2)`: residual 1.3e-15 but the projections differ by 75%; stacked `xs + xs`: 44%;
  full-rank control: 3e-16.
- `uniform_rankdef_apples.py`: locates the defect — the converted frame has **zero slices inside real mask slots**
  (`down[2]` zero along axes 0,1; `left[2]`, `right[0]`, `down[1]`, `right[1]` likewise). Given the *same* frame
  (uniform frame converted with `to_t3frame()`), ragged and uniform `project_ambient` agree to 2e-16 and both equal
  the dense least-squares projection onto the span of the tangent basis → the backends are consistent; it is the
  **frame construction** that differs: the uniform sweep leaves the directions with zero singular value as zero
  columns instead of completing the basis (as LAPACK/ragged does), so the tangent space loses those directions.
- `uniform_resized_x0_fit.py`: `newton_cg` from the same zero-padded x0, ragged vs uniform manifold (probe kind):
  objective after 4 steps 6.05e4 (ragged) vs 8.08e4 (uniform); the uniform run does **not** raise in safe mode
  (the optimizer builds its geometry through `backend/geometry.py` and never checks), so it silently optimizes in a
  smaller tangent space. (Relation to `docs/contributor/sharing_internals.md` "padded-restart ... momentarily gated":
  on the uniform layer the gating is a non-orthogonal frame, not a transient.)
- `uniform_stacked_frame.py`: stacked `(2,)` `x + x` at `(4,6),(2,3),(1,2,1)`: element 0 orthogonal, element 1
  residual 1.0 (up[0] and down[0..1] zero columns) — per-stack-element, so `is_orthogonal()` is `[True False]`.
Root-cause line not pinned (time box); suspect the `ss·Vt` remainder / masking in the up/down sweep of
`ufv_conversions.ut3_orthogonal_representations` + `ut3_orthogonalization.py:95-150`. Fix: complete the basis
(use the full SVD `U` columns regardless of `ss`), or shrink the masks to the numerical rank when `ss == 0`.
Related ledger: `deferred_and_rejected.md` "d = 1 on the uniform layer" (different issue), `uniform_svd_prefix_orthogonalization.md`.

### H4-3 (C, confirmed) — d=1: `MANIFOLD.project_ambient(frame, T3)` and `MANIFOLD.transport` crash (IndexError)
`t3toolbox/backend/tt_operations.py:180` (`tt_zipper_left_to_right`: `coresA[0].shape` on an empty list) via
`tv_operations.py:402` (`tv_project_t3_onto_tangent_space` passes `other_tt_cores2[:-1]`, empty when d=1).
`matrix_ragged_tangent.out`: `d1`/`d1_square` × every stack: `manifold_project_ambient_t3`, `manifold_project_ambient_t3svd`
(the dense `method='t3svd'` route goes through the same function) and `manifold_transport` all fail on numpy, jax
and jit; `project_ambient(frame, dense)` (contraction method) works for d=1, as does everything else at d=1
(to_dense, probe/apply/entries + transposes + derivatives, project, retract, t3svd, newton_cg all kinds).
Ragged d=1 is a supported structure (the ledger only excludes uniform d=1). Fix: early-return the empty zipper
(`if not coresA: return ()`-style) in `tt_zipper_left_to_right`/`right_to_left`.

### H4-4 (C, confirmed) — `stacking.stack` is not jittable: `xnp.arange` used as static `moveaxis` source
`t3toolbox/backend/stacking.py:261`: `xnp.moveaxis(stacked, source=xnp.arange(len(axes)), destination=axes)`.
Under `jax.jit`, `jnp.arange` is a tracer → `ConcretizationTypeError: Abstract tracer value encountered ... int64[1]`.
Reached by `TuckerTensorTrain.stack`, `T3Frame.stack`, `T3Variations.stack`, `T3Tangent.stack_tangents`,
`UniformTuckerTensorTrain.stack`, `UT3Tangent.stack_tangents` (`matrix_ragged_t3.out` `stack_unstack`,
`matrix_ragged_tangent.out` `stack_tangents`/`unstack_tangents`, `matrix_uniform.out`; direct repro in the
`T3Frame.stack jit` / `T3Variations.stack jit` rows of the follow-up script output quoted in the lane log).
Eager jax works; `unstack` is fine under jit. Fix: `source=tuple(range(len(axes)))`.

### H4-5 (C, confirmed, minor) — `TuckerTensorTrain.has_numerically_minimal_ranks()` raises on a stacked train
`t3toolbox/tucker_tensor_train.py:721`. For a stacked train that is structurally minimal, the method calls
`t3svd(rtol=...)`, which raises `ValueError: Cannot use rtol or atol with t3svd for stacked Tucker tensor train.`
(`matrix_ragged_t3.out`: `d2_rank1 (1,)/(2,)`, `d3_rank1 (1,)/(2,)`). The docstring does not restrict to unstacked.
Fix: loop over `unstack()` and return a per-element bool array, or document.

### H4-6 (E, confirmed) — `assert`-guarded structural checks vanish under `python -O` (silent truncation / broadcast)
29 sites: `corewise.py:61,62,84,85,210,211,241,242`; `backend/ranks.py:111,112,342,353,354,537,538`;
`backend/t3_linalg.py:61,117,195,258`; `backend/t3_operations.py:296,297`; `backend/common.py:346,352,369,375,390,396`;
`backend/probing.py:1514,1515`; `tucker_tensor_train.py:2023`. `asserts_under_O.py` with `-O`:
`corewise_add/sub/dot` on a 3-vs-2-element tree **return a 2-element result** (zip truncation) instead of raising;
`x * np.ones((4,5,1))` (wrong dense shape) **returns a broadcast (4,5,6) array** instead of raising;
`t3_sum(axis=5)`, `compute_minimal_ranks` bad lengths degrade to `IndexError`. Without `-O` all raise `AssertionError`
(no message). House rule: structural problems always error. Fix: replace with explicit `raise ValueError(...)`.

### H4-7 (C, confirmed; broadens a known item) — jax absent: `randn(use_jax=True)` is a bare `NameError`; `to_jax()`/`load(use_jax=True)` silently return numpy
`t3toolbox/backend/common.py:405-407` (`randn`: `jnp.array(...)` with `jnp` unbound) — reached by
`TuckerTensorTrain.randn(..., use_jax=True)` and `UniformTuckerTensorTrain.randn(..., use_jax=True)`
(`jax_absent.py`: `NameError: name 'jnp' is not defined`), independent of the known `get_backend` NameError.
`common.py:102` `to_jax = lambda x: np.array(x)` when jax is absent, so `x.to_jax()`, `T3.load(f, use_jax=True)`
and `tree_to_jax` return **numpy** arrays without any error, contradicting `to_jax`'s docstring
("Convert core arrays ... to Jax arrays") and `load`'s "Cores are jax arrays if True". `newton_cg(use_jit=True)` does
raise a clear message (good). Fix: one `_require_jax(what)` helper raising `ImportError('... install t3toolbox[jax]')`
used by `get_backend`, `randn`, `to_jax`.
Related known: HANDOFF backlog "get_backend raises a bare NameError".

### H4-8 (E, confirmed) — `TuckerTensorTrain` has no `__rmul__`
`t3toolbox/tucker_tensor_train.py:1934`. `2.0 * x` → `TypeError: unsupported operand type(s) for *: 'float' and 'TuckerTensorTrain'`,
while `x * 2.0` works and `UniformTuckerTensorTrain`, `T3Tangent`, `UT3Tangent` all define `__rmul__ = __mul__`.
(`matrix_ragged_t3.out`, `mul_scalar` rows.) Fix: add `__rmul__` for the scalar case.

### H4-9 (S suspected / D, partially confirmed) — the documented `T3FrameWeights.from_t3weights(T3Weights.from_t3svd(x))` + `t3_orthogonal_representations(x)` pairing is gauge-fragile for stacked input
`docs/weighting.md:79-82` builds the frame with `t3_orthogonal_representations(x)` and the metric from `x`'s σ's.
The σ-weights are coordinates in the **t3svd gauge**. Measured (inline script, output in the lane log): for
`xs = x.t3svd()[0]` unstacked, the frame's up cores equal the t3svd factors up to sign (numpy and jax) — fine. For
`stack_shape=(2,)` they do **not** (`frame up cores == t3svd tucker cores up to sign: False`), i.e. the stacked sweep
rotates the Tucker factors, so the σ-weights are applied to rotated coordinates; `matrix_ragged_tangent.out`
`d2 (2,) tangent_absorb_weights np/jax MISMATCH relerr 7.0e-01` and the uniform `d2 () tangent_absorb_weights 9.3e-02`,
`ufv_absorb_weights 1.4` are this gauge dependence surfacing as numpy-vs-jax disagreement on the same input
(`weighted_norm` agreed because the norm is rotation-invariant only when weights are equal — it did agree here by
structure, not by design). Confirmation needed: show `weighted_norm` differs from the dense σ-weighted norm for a
stacked `xs`. Fix/doc: build the frame with `T3Frame.from_t3(xs)` (no re-orthogonalization) when pairing with
`from_t3svd` weights, and say so in `weighting.md`; or make `t3_orthogonal_representations` preserve an already
orthogonal Tucker factor.

### Non-findings / confirmations (for the consolidation step)
- **No numpy-vs-jax or eager-vs-jit value mismatch** in any ragged or uniform op on any edge structure (rank-1,
  mode size 1, square Tucker factors, non-minimal TT ranks, d=1..4, stacks `()`, `(1,)`, `(2,)`), except H4-9.
- **No jax-in→numpy-out leak** anywhere (ragged cores, uniform supercores; masks numpy by design).
- **Mixed numpy/jax operands** (`x_np + x_jax`, `x_np.probe(ww_jax)`, `T3Tangent(np frame, jax variations)`,
  uniform mixes) all dispatch to jax. (`np_tangent + jax_tangent` built from separate `t3_orthogonal_representations`
  calls fails the same-frame check because numpy's and jax's SVD choose different signs — legitimate.)
- **Fitting**: `newton_cg` numpy vs `use_jit=True` (x64) agree to 1e-6 for all 6 kinds × 3 geometries × 5 edge
  structures (`fit_edge_jit.out`; the `d1` row is 5.0e-29 vs 5.1e-29, noise). d=1 fits work.
- **Uniform weighted layer under jit** (`ut3_weighted_norm/inner`, `ut3_absorb_weights`, `UT3Weights`
  `sqrt/reciprocal/kronecker/concatenate`, `UT3FrameWeights.from_ut3weights/reciprocal`, `ufv_absorb_weights`,
  `UT3Tangent.absorb_weights/weighted_norm`) — jit-clean, values match numpy (the HANDOFF "zero positive jit
  coverage" item is a missing test, not a bug).
- jax absent: every numpy path tried works (ragged/uniform sampling, derivatives, manifold ops, weights,
  `newton_cg` ragged+uniform incl. `chunk_size='auto'`, save/load, `xwhile(use_jit=True)` eager fallback).
- `COREWISE.retract` on an *orthogonal* frame with `nU != nD` (e.g. `(4,6),(2,3),(1,2,1)`) fails with a raw
  broadcast error; the docstring says `p` must be a `COREWISE.frame` tangent, so this is a misuse with an
  unhelpful message (E, not listed separately).
- `has_numerically_minimal_ranks`, `t3svd(rtol)`, `continuation_ranks` give identical ranks on jax float32 and numpy
  for the cases tried (no float32 tolerance surprise there).
