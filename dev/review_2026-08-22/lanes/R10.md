# Lane R10 — weighted (edge-weight) layer

Scope: `T3Weights` / `T3FrameWeights` / `UT3Weights` / `UT3FrameWeights`, their backends
(`t3_operations.t3_*_weights`, `t3_linalg.t3_weighted_*`, `fv_operations.fv_*`, `ut3_operations.ut3_*_weights`,
`ut3_linalg.ut3_weighted_*`, `ufv_operations.ufv_*`, `utv_operations.ufv_weighted_*`), the tangent methods
`absorb_weights` / `weighted_norm` / `weighted_inner` (ragged + uniform), `from_t3svd` / `from_ut3svd`,
`t3weights_to_t3frameweights`, the ragged<->uniform weight conversions, `docs/weighting.md`,
`docs/contributor/weighted_internals.md`.

Repro scripts: `scratchpad/repros/R10/` — `r10_identities.py` (ragged dense identities), `r10_batching.py`
(C-vs-K+C at every entry point), `r10_uniform_equiv.py` (uniform == ragged; from_*svd; reciprocal/sqrt zeros;
frame weights), `r10_jit.py` (jit of every op + two grads), `r10_grad.py` / `r10_grad_uniformrank.py`
(differentiability), `r10_d1_uniform.py` (d=1), `r10_padded_gk.py` (GK metric on a padded train),
`r10_jit_stack.py` (stack/unstack under jit). Baseline: `tests/test_weighted.py` + `tests/test_uniform_weighted.py`
pass (51 tests / 123 subtests).

## What was checked, and the result

**Dense identities, ragged (`r10_identities.py`)** — minimal-rank asymmetric structures
`(5,6,7)/(2,3,3)/(1,2,3,1)`, `(4,7,5,6)/(2,3,3,2)/(1,2,4,2,1)`, `(6,5)/(3,3)/(1,3,1)`, `(9,)/(1,)/(1,1)` ×
stacks `(), (1,), (2,), (2,3)`; K=(3,) at the tangent level. All worst relative errors ≤ 2.4e-14:
absorb == independent hand-einsum with the diagonals inserted; `t3_weighted_norm` == dense norm ==
`absorb(x,W).norm()`; `t3_weighted_inner` == dense inner; **`+` ↔ `concatenate`** holds with the frontend `x + y`
(which returns `t3_add` *unsquashed*, boundary bonds 2 — `W.concatenate(W2)` is consistent with it, and NOT with
`(x+y).squash_tails()`); **Hadamard ↔ `kronecker`** holds with the library `x * y` (`t3_mult`; A-major agrees);
`reverse` (tensor and frame weights) commutes with `x.reverse()` / `tangent.reverse()`; `stack(unstack())`
round-trips and leaves index correctly; all-ones identity; `W` then `1/W`; `sqrt`. Frame weights: `weighted_norm`
== absorbed `corewise_norm`, `weighted_inner` == absorbed `corewise_inner`, absorbed V/H cores == hand scaling,
backend `fv_weighted_norm/inner` == frontend, result shape `K+C`.

**Batching rule (`r10_batching.py`)** — tangent level (ragged `T3Tangent.*` and uniform `UT3Tangent.*`, plus
`check_fw_pair`/`check_ufw_pair`): `C` accepted; `K+C` (K-tiled) and `()` rejected with the documented message.
Variation level (`fv_absorb_weights`, `ufv_absorb_weights`, backend `fv_/ufv_weighted_norm`,
`is_consistent_with`): trailing rule, all three accepted, K-tiled == C numerically — as documented ("blind to the
frame"). Tensor level: uniform `ut3_absorb_weights`/`ut3_weighted_norm` reject `(3,)+C` and `()`; **ragged
`t3_absorb_weights`/`t3_weighted_norm` accept both and broadcast** (a `(3,)+C` weight yields a `(3,2)`-stacked
result; `is_consistent_with` says False), and `t3_weighted_inner` with such a weight dies with a **bare
`AssertionError`** from `t3_inner_product` (R10-6).

**Uniform == ragged (`r10_uniform_equiv.py`)** — trains padded above their real ranks, stacks `(), (2,), (2,3)`:
absorb, norm (orth and no-orth), inner, concatenate/kronecker (values through `to_t3weights`), reciprocal/sqrt —
all ≤ 1e-9 (mostly exact). `UW.concatenate(UW2)` is consistent with the **backend `ut3_add`** (unsquashed) and the
dense `+` identity holds there; it is **not** consistent with the frontend `ux + uy` (which squashes) — R10-2.
Frame weights at C=(2,), K=(3,): uniform == ragged to 4e-16 for norm/inner/absorb/concat/kron/recip/sqrt.
`from_ut3weights(from_ut3svd(ux))` pairs with `ut3_orthogonal_representations(ux)` only when `ux` is tightly
padded (R10-4, `r10_padded_gk.py`).

**from_t3svd / from_ut3svd** — ragged: `tt_weights[0] == tt_weights[-1] == [‖x‖]` (len d+1, the sval format),
consistent with a minimal-rank `x`, `weighted_norm == norm(absorb)`. A non-minimal `x` (ranks 4 on a
rank-3-capable structure) gave from_t3svd ranks still consistent here (randn is generically full rank), and the
docstring covers the truncating case. `from_ut3svd` on a padded-above train: `W.n < ux.n`, `is_consistent_with`
False, `ut3_weighted_norm` raises — as the `from_ut3svd` docstring says ("tight padding"); the workaround it
gives works. The HANDOFF "two SVDs" item (`:181`) is the known cost.

**reciprocal / sqrt** — real zero: ragged `inf` + numpy `RuntimeWarning`; uniform `inf` in the real slot, padding
finite `0` (guarded), same warning. Negative real: `nan` in both. As documented ("real-slot zeros deliberately
not guarded").

**jit (`r10_jit.py`)** — every public weighted op, ragged and uniform, frontend and free function, compiles and
matches eager (tol 1e-4 at float32; svd-based 1e-3): 40/42 OK. The two failures are `T3Weights.stack(unstack())`
and `T3FrameWeights.stack(unstack())` — inherited from `stacking.basic_ragged_stack`
(`TuckerTensorTrain.stack(x.unstack())` fails identically; `unstack` alone is fine) — R10-5. `check_fw_pair` /
`check_ufw_pair` / `is_consistent_with` run inside a trace (host masks). `to_t3weights` / `to_t3frameweights`
(stacked → tree, boolean-mask gather) work under jit as `weighted_internals.md` claims.

**Gradients (`r10_grad.py`, `r10_grad_uniformrank.py`)** — ragged `t3_weighted_norm`, `x.norm()`,
`T3Tangent.weighted_norm` (wrt tangent and wrt W) all finite. **Uniform `ux.norm()`, `ut3_weighted_norm`
(default `use_orthogonalization=True`, wrt ux and wrt W) and `ut3_weighted_inner` give all-NaN gradients** on
both a tightly padded and an over-padded train; finite with `use_orthogonalization=False`, finite at the tangent
level, and finite on a fully uniform-rank train (no slack anywhere). The NaN is the SVD-based uniform
orthogonalization at padded (zero) singular values — `_ut3_left_orthogonalized`. Not in the ledger. R10-1.

**d=1 uniform (`r10_d1_uniform.py`)** — `ux.norm()`, `ux.inner_product`, `ux.t3svd()`, `ut3_weighted_norm`
(both paths) all raise at d=1 (`tt_orthogonalization.tt_left_orthogonalize:62` concatenates the empty tuple
`LL0=()` with a 4-D array; `ut3svd_supercores` too). The ledger (`deferred_and_rejected.md:41`) records only the
`ut3svd_supercores` site and frames it as "uniform fit"; it is broader — plain norm/inner. R10-3.

**Docs claim-by-claim** — `docs/weighting.md`: the absorb side-convention, shape/rank preservation, the
`+`/`⊙` duality (ragged), the four-family table, "absorbed into the variations / frame untouched / not gauged",
all-ones == corewise_norm, `from_t3weights` slicing (`left = tt[:-1]`, `right = tt[1:]`) and the printed ranks,
the sharing paragraph (group-equal by construction; algebra preserves it — trivially, per-edge ops), the
Batching section (C not K+C; trailing rule at the variation level; exact at the tangent level), the uniform
bullets (masks must match; reciprocal guards padding; gappy masks) — all verified true. False/overstated:
`:184` and `:208-209` (uniform `reverse/stack/unstack`) — **known, not re-reported**; the `+` ↔ `concatenate`
duality as a uniform-frontend statement — R10-2. `weighted_internals.md`: "no `ut3_mult`" true (grep);
"boolean indexing works under jit" true; `check_fw_pair` named as the public guard but not exported — R10-7.

**Shape comments / signatures** — `T3Weights` fields DO carry `len=d` / `len=d+1` (tucker_tensor_train.py:4671-4672),
so HANDOFF:205 is stale for the class; the backend parameter comments (`# (tucker_weights, tt_weights)`) still omit
the lengths (docstrings state them) — R10-8. Minor asymmetries (R10-9): ragged frontend `t3_weighted_norm/inner`
lack `use_orthogonalization`; `T3Tangent.weighted_norm/inner` have no return annotation/shape comment while the
uniform twins do; conversion signatures write `n: int = None`.

**Untested public names** (grep of tests/): `fv_weights_consistent`, `fv_concatenate_weights`,
`fv_kronecker_weights`, `t3weights_to_t3frameweights`, `t3_weights_consistent`, `t3_concatenate_weights`,
`t3_kronecker_weights`, `ut3_weights_consistent`, `ut3_sqrt_weights`, `ut3_concatenate_weights`,
`ut3_kronecker_weights`, all `ufv_*_weights`, `ufv_weighted_inner`, `t3weights_to_ut3weights`,
`t3frameweights_to_ut3frameweights`, `ut3frameweights_to_t3frameweights` are reached only via frontend methods.
All were exercised here through those methods against dense / ragged oracles and are correct. One genuine test
gap: `test_concatenate` (ragged) checks per-edge values only, never the dense `+` identity (it holds — verified).

## Findings (detail in the structured output)

- R10-1 S: NaN `jax.grad` through `ut3_weighted_norm` / `ut3_weighted_inner` (default path) and `ux.norm()` on any
  train with rank slack. `backend/ut3_linalg.py:204`.
- R10-2 D: `docs/weighting.md` `+`↔`concatenate` does not hold for the uniform frontend `+` (squashes tails);
  `UT3Weights.concatenate` "partner of `ut3_add`" is backend-only. `docs/weighting.md:46`, `uniform_tucker_tensor_train.py:1139`.
- R10-3 C (broader than known): uniform d=1 also breaks norm/inner/weighted norm in `tt_left_orthogonalize`. `backend/tt_orthogonalization.py:62`.
- R10-4 E: `from_ut3svd` shrinks the pad, so the documented GK route fails against a padded train's frame; only a ragged detour works. `uniform_tucker_tensor_train.py:1158`.
- R10-5 E: `stack(unstack())` under jit fails (general `basic_ragged_stack`). `backend/stacking.py:452`.
- R10-6 E: ragged tensor-weight ops silently broadcast a mis-stacked weight; `t3_weighted_inner` then bare-asserts. `tucker_tensor_train.py:4793`, `backend/t3_linalg.py:195`.
- R10-7 E: `check_fw_pair` not exported while `check_ufw_pair` is. `frame_variations_format.py:30`.
- R10-8 E: HANDOFF:205 stale (class fields have the lengths); backend param comments still lack them. `backend/t3_operations.py:328`.
- R10-9 E: signature asymmetries (`use_orthogonalization`, return annotations, `int = None`). `tucker_tensor_train.py:4800`.
