## Findings (ranked)

### R3-1 — S (confirmed): `compute_orthogonal_representation_ranks` predicts the wrong left/right TT ranks on non-minimal input; the uniform frame masks are built from it, so `UT3Frame.from_ut3` / `UNIFORM_MANIFOLD.frame` return a NON-orthogonal frame on a valid non-minimal point

`backend/ranks.py:496-586`. The map said this function has no caller; it does — `backend/ufv_conversions.py:107`
uses it to build the uniform frame's prefix masks (`ufv_make_frame_masks`). Its recurrence does not follow the
sweep the library actually runs (`fv_conversions.t3_orthogonal_representations`: Tucker down-orth, **left**
sweep on the original bonds, then a **right** sweep over the left-orthogonal chain). The code instead computes a
right sweep over the *original* bonds first and derives the left ranks from that (`:549-564`):

```
code:    right_i = min(r_i, n_i * right_{i+1})          (right sweep over the ORIGINAL bonds)
         left_{i+1} = min(left_i * n_i, right_{i+1})
actual:  left_{i+1} = min(left_i * n_i, r_{i+1})        (left sweep over the ORIGINAL bonds)
         right_i = min(left_i, n_i * right_{i+1})        (right sweep over the LEFT-orthogonal chain)
```

`orth_rep_ranks.py`: 185/303 random structures (d in 1..4, asymmetric) disagree with the ranks
`T3Frame.from_t3` actually produces; every minimal-rank structure agrees (the test suite's structures are
minimal, which is why nothing caught it). Example `shape=(5,5,5), n=(2,2,2), r=(1,4,4,1)`: predicted
`left=(1,2,2,1) right=(1,4,2,1)`, actual `left=(1,2,4,1) right=(1,2,2,1)`. `orth_rep_fix.py`: the corrected
recurrence above reproduces the actual ranks in 301/301 cases.

Consequence (`orth_rep_fix.py`, `safe_mode_uniform_frame.py`): on that point `T3Frame.from_t3(x).is_orthogonal()`
is True (residual 9e-16) but `UT3Frame.from_ut3(from_t3(x)).is_orthogonal()` is **False** (residual 4e-2; on the
`minimal_ranks` doctest's own structure `(13,14,15,16),(4,5,6,7),(1,4,99,7,1)` the residual is **1.0** and the
right mask admits rank 42 where the content rank is 20). `UNIFORM_MANIFOLD.frame(u)` is the same frame. In safe
mode `UNIFORM_MANIFOLD.project_ambient(ufr, ug)` raises the *orthogonality* precondition error (obscure — the
user did nothing wrong); in unsafe mode / under jit it returns a projection that differs from the ragged one by
**29%** (control on the minimal point: 5e-16). `docs/uniform_equivalence_contract.md:33` states "The contract
holds on non-minimal-rank input too". The optimizers are shielded only because `optimizers.py:186` calls
`uniform_minimal(x0)` first; `UT3Frame.from_ut3`, `UNIFORM_MANIFOLD.frame/project/retract/randn` on a
hand-built non-minimal uniform point are public, undocumented-precondition paths.

Fix: replace `:548-573` with the corrected recurrence (left sweep first on `tt_ranks`, right sweep over
`left_ranks`, `down_i = min(up_i, left_i * right_{i+1})`), add a direct test of this function against
`T3Frame.from_t3` core shapes on random **non-minimal** structures, and a uniform-frame orthogonality test on a
non-minimal point. (Also `compute_orthogonal_representation_ranks` has no docstring beyond one line and no test —
the map's "no caller" was wrong, the "no test" was right.)

### R3-2 — D (confirmed): `rank_adjustment_sweep` "compose both directions for guaranteed minimal ranks" is false when a Tucker rank exceeds its mode size (`n_i > N_i`)

`backend/t3_svd.py:303-306,314`, `tucker_tensor_train.py` (`rank_adjustment_sweep` docstring), `docs/t3svd_minimal_ranks.md`
("compose both directions ... for guaranteed minimal ranks"), `docs/contributor/t3svd_design_rationale.md`. The
sweep re-SVDs only the TT core's outer unfolding (`t3_down_svd_tt_core`), never the Tucker factor itself, so the
`n_i <= N_i` ceiling is never applied. `sweep_N_ceiling.py`, on the `minimal_ranks` doctest structure
`(13,14,15,16),(4,99,6,7),(1,4,9,7,1)`: `minimal_ranks = ((4,14,6,7),...)`, but R->L then L->R (and L->R then
R->L) give `n_1 = 36` (= rL*rR) with `has_minimal_ranks == False`; `t3svd()` gives 14 (it down-orthogonalizes
first). Shared variant identical: group `n=5 > N=3` -> composed shared sweeps keep 5 where
`compute_minimal_ranks(sharing)` and `t3svd(sharing)` give 3. Lossless (tensor unchanged), so D not S. With
`n_i <= N_i` the composed sweeps reach the minimal ranks in 150/150 unshared and 150/150 shared random cases.
Fix: SVD the Tucker factor (a down-orthogonalization of `B_i`) inside the Tucker step, or state
`n_i <= N_i` as a precondition of the "guaranteed minimal" claim (the `minimal_ranks` doctest shows such inputs are legal).

### R3-3 — D (confirmed): the tolerance rule documented is "drop sigma < max(atol, rtol*sigma1)" / "r_hat <= #{sigma >= tau}"; the code keeps by **tail Frobenius energy** against `rtol*||A||_F`

`backend/linalg.py:81-82, 102, 105` (signature comments + Parameters: "removes singular values satisfying
sigma < maximum(atol, rtol*sigma1)"), `docs/contributor/t3svd_verification.md` (the Claim `r̂_k <= #{σ >= τ}`,
its "proof" — "The routine chooses r̂_k = #{ j : σ_j(unfold_k(C_k)) >= τ_k }" — and Algorithm 2), and the
`TuckerTensorTrain.t3svd` doctest comment "parsimony: each chosen rank <= #{ original singular values >= tau }".
The code (`linalg.py:201-205`) keeps `K = #{ j : ||sigma[j:]|| >= max(rtol*||A||_F, atol) }`, which keeps at
least as many and can keep far more. `tol_parsimony.py`: spectrum `[1, 0.05 x20]`, `rtol=0.08`: per-sigma rule
keeps 1, code keeps 19. Through `t3svd(rtol=0.1)` on a flat-tailed tensor the chosen Tucker ranks are `(6,7,6)`
where the doc's bound `rho` is `(1,6,6)` — the Claim is violated. The tail-energy rule is the *right* one (it is
what makes the accumulated-error bound `||x-x2|| <= sqrt(2d-1)*tol` hold), and the actual tests
(`test_tucker_tensor_train.py:2587-2590, 2929-2933`) already use tail energy — only the docs/comments/doctest
comment are stale. The doctest passes by luck of the graded spectrum. Fix: restate the rule as tail energy in
`linalg.py`, rewrite the verification note's Claim/Alg 2 as "r̂ <= #{ j : ||σ_{j:}|| >= τ }" (the projection
lemma still proves it, since tails also contract), and fix the doctest comment.

### R3-4 — C (confirmed; broader than the ledger entry): d = 1 breaks the whole uniform SVD/frame surface, not only fits

`backend/ut3_svd.py:280` (and `:378`). `d1_uniform.py`: on `from_t3(randn((6,),(3,),(1,1)))` every one of
`t3svd()`, `t3svd(max_tucker_ranks=2)`, `t3svd(assume_orthogonal=True)`, `rank_adjustment_sweep()` (both
directions), stacked/padded variants, fails with `ValueError: ... along dimension 0, the array at index 0 has
size 2 and the array at index 1 has size 1` (after orthogonalization the tt supercore arrives with leading dim
d+1 = 2). Additionally `UT3Frame.from_ut3(u)` fails with a shape-validation error and `u.is_left_orthogonal()`
fails with "zero-size array to reduction operation maximum". Ragged d=1 is fine. The ledger
(`deferred_and_rejected.md:41`) describes it as "any uniform *fit*"; it is every uniform SVD / frame /
orthogonality-check call. related_known: that ledger entry.

### R3-5 — D (confirmed, minor): `dense_tucker_svd` / `dense_ttsvd` docstrings describe a nonexistent `xnp` parameter and "See Also" nonexistent names

`backend/t3_svd.py:451-452, 561-562` ("xnp: Linear algebra backend. Default: np") — no such parameter (dispatch is
inferred). `:463-466, 573-576` list `tt_svd_dense`, `t3_svd_dense`, `t3_svd`; the real names are `dense_ttsvd`,
`dense_t3svd`, `t3svd` (grep: no such defs anywhere). Also `dense_ttsvd`'s shape comment says `(N0,...,N(d-1))`
while its Parameters say `(N1, ..., Nd)`.

### R3-6 — E (confirmed): `truncated_svd` lets `min_rank` silently override `max_rank`

`backend/linalg.py:207-209`: `r = max(min(K, max_rank), max(1, min_rank))`. `truncated_svd(A, min_rank=5, max_rank=3)`
keeps 5. The docstring states `min_rank <= max_rank` as a precondition but nothing checks it; reachable from
`dense_tucker_svd(min_ranks=..., max_ranks=...)` / `dense_ttsvd`. A structural inconsistency by the house rule,
so it should raise. (`safe_mode_uniform_frame.py`, last line.)

### R3-7 — E (confirmed, not worse than known): `np.minimum` in `ranks.py`

`np_minimum_jax.py`: with jax inputs and `use_jax=True` all three functions work eagerly (they return jax
arrays); under `jax.jit`, `compute_minimal_ranks` and `compute_orthogonal_representation_ranks` raise
`TracerArrayConversionError`, `compute_raw_sweep_ranks` traces fine. No in-library caller passes traced ranks
(all pass host mask sums or Python tuples), so this is the already-listed convention item, not a live bug.
related_known: the brief's "np.minimum mixed into xnp functions in ranks.py".

## Candidates verified and refuted (no finding)

- `compute_raw_sweep_ranks(sharing=)` == the grouped `t3svd(sharing, caps)` output ranks: 200/200 random
  tied structures (d 2..4, asymmetric sizes/ranks, random per-group Tucker caps and per-bond TT caps). `shared_ranks.py`.
- `compute_minimal_ranks(sharing=)` == dense edge-cut ranks (rank of the concatenated group matricization
  `[T_(i1)|...|T_(ik)]`, TT unfolding ranks) of a random tied T3: 200/200. == the composed two-direction shared
  sweeps whenever `n_i <= N_i`: 150/150 (the `n_i > N_i` failure is R3-2, a sweep limitation, not a ranks bug).
- A single L->R grouped sweep on a right-orthogonal tied input reaches the shared-minimal ranks: 200/200 — so the
  uniform `_reduce_left_to_right`'s "masks = compute_minimal_ranks" assumption is sound; uniform
  `rank_adjustment_sweep('right_to_left', sharing)` on `ut3svd(sharing)` outputs was lossless with masks equal to
  the ragged ranks in 60/60.
- `ut3svd(sharing=)` exact output masks, real parts and masked spectra vs the per-element ragged grouped `t3svd`
  on two-element **varying-rank** stacks with **per-element** caps: 120/120 elements. `uniform_shared_masks.py`.
- The open-coded sharing normalizations: all-singletons, one group covering all modes, non-contiguous groups
  (`(0,2)`, `(0,3),(1,2)`) through the ragged R->L mode reversal (`_reversed_groups`) and the uniform reversal
  (`tuple(reversed(sharing))`): lossless, tied (same array object), group spectra equal, right-orthogonal output,
  ranks == `compute_minimal_ranks(sharing)`. Passing a canonical `groups` tuple where labels are expected is
  self-protecting: it either raises (length mismatch) or is the all-singleton case. `groups_to_labels` round-trips.
  `partition_edges.py`.
- `t3_share_tucker_factors`: on tied input equals the grouped `t3svd` (tensor and spectra); stacked == per-element;
  quasi-optimality never violated against the provable lower bound on the best shared approximation (tail of the
  group concatenated-matricization spectrum / sqrt(k), TT tails): worst `err/LB = 1.39` vs `C(3) = 5.60`, 40
  cases. (Not checked against the true optimum — only the lower bound.) `share_quasi.py`.
- `docs/t3svd_minimal_ranks.md` "tolerance results are already minimal": 0/400 non-minimal tolerance-truncated
  results on graded random T3s. `tol_parsimony.py`.
- `t3svd` rtol/atol/max_ranks interplay: `rtol`/`atol` with a stack raise at the frontend (documented); caps and
  tolerance combine as `min(K_tol, cap)` (documented precedence matches code); the `_t3svd_shared` docstring's
  rank bound is stated in tail-energy terms (consistent with code).
- `edge_condition_numbers`: conventions (empty -> 1, all-zero -> 1, deficient -> inf, boundary bonds 1.0) match
  docstring and `docs/rank_continuation.md`; `compute_continuation_ranks`' uniform-spectra warning is accurate in
  mechanism (reads `len(s)`).
- Paper: `t3svd` is Algorithm 10 (orthogonalize, then per mode Tucker SVD then bond SVD) — matches; `dense_t3svd`
  is Algorithm 9 — matches; the Algorithm-11 sweep-order divergence is the known deliberate one.
