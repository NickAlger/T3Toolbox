# Lane R5 — sampling: probe / apply / entries (backend + frontend wrappers)

Scope: `t3toolbox/backend/{probing,apply,entries}.py`, the `TuckerTensorTrain.{entries,apply,probe,*_ambient_transpose,*_corewise_transpose}` and `T3Tangent.{probe,apply,entries,*_transpose}` wrappers, `MANIFOLD.project_ambient` from samples, `docs/entries_apply_probe.md`, `docs/transposes.md`, paper §6.2 (Algs 5–8) and §6.3.

## What I checked and how

**Sweep (`r5_core_checks.py`)** — 6 structures × 6 stack triples, all asymmetric (distinct `N`, distinct Tucker and TT ranks, non-square cores), `d ∈ {1,2,3,4}`, boundary TT ranks both `1` and `≠1` (the library allows `(2,3,4,2)`; its own doctest uses it), stacks `(W,K,C) ∈ {((),(),()), ((1,),(),()), ((2,),(),(3,)), ((2,),(3,),()), ((2,),(3,),(4,)), ((2,2),(3,),(4,))}` — the distinct non-broadcastable sizes `2/3/4` so a `W`/`K`/`C` transposition would be caught by shape alone. Per case:

- `probe`/`apply`/`entries` vs dense (`dense_probe`, hand einsum, dense indexing) — **pass** for all `d ≥ 2`, all stacks; `d=1` passes wherever the oracle itself runs.
- Tangent `T3Tangent.probe/apply/entries` on a `K`-stacked tangent at a `C`-stacked frame vs `dense_probe`/einsum/indexing of `v.to_dense()` (`K+C+N`) — **pass**; output shapes asserted to be exactly `W+K+C(+Ni)`.
- Adjoint identities `⟨z, 𝒥v⟩ = ⟨𝒥ᵀz, v⟩` for all three ops with residuals `W+K+C`, both `sum_over_probes` (`True`: total sum; `False`: per-`W` element) — **pass**; result `tangent_stack_shape` asserted `K` / `W+K`, `frame_stack_shape == C`.
- **All 13 reuse hooks**: `tv_precompute_{probe,apply,entries}_frame_sweep` + `tv_{probe,apply,entries}_{jacobian,transpose}_from_sweep` — precompute-then-apply equals the one-shot function to 1e-13 at every case (they share code paths, so this is expected, but it was untested). Also jit-smoke'd under jax (`r5_edge_cases.py` §I) — compile and run.
- Corewise transposes (`{apply,entries,probe}_corewise_transpose`, the §6.3 substitution) vs the EXACT corewise Jacobian built by single-core replacement — **pass**, both `sum_over_probes`, `W` kept as leading stack on every gradient when `False`.
- Ambient transposes (`C=()`): `⟨from_canonical(op_ambient_transpose(c)), X⟩_F == ⟨c, op(X)⟩` — **pass**, both modes; CP-rank folding with `sum=True` gives an unstacked tensor, `sum=False` a `W`-stack.
- `docs/transposes.md` claim "tangent = ambient back-projection projected onto the gauged tangent space": `MANIFOLD.project_ambient(frame, from_canonical(ambient))` (both the T3 and the dense path) equals `MANIFOLD.project(T3Tangent.op_transpose(...))` to 1e-8 for all three ops, `d ≥ 2` — **confirmed true**.
- Paper ↔ code, line by line: Alg 5 (`compute_xi/mu/nu/eta`, `assemble_z`), Alg 6/7 (`compute_dxi/sigma/tau/deta`, `assemble_tangent_z` — every term of lines 3–6 matched against `_sigma_step`, `_deta_step`, `_assemble_tangent_z_step`), Alg 8 (lines 1–7 matched against `compute_deta_tilde/tau_tilde/sigma_tilde/dxi_tilde`, `_assemble_tucker_variations_core`, `_assemble_tt_variations_core`), §6.3 (`fv_conversions.t3_corewise_frame` → `(U,G,G,G)` = `(up, down, left, right)`). `docs/entries_apply_probe.md` §8 table rows all correct. No divergence found.
- Delegate argument order: every `probing.*` call in `apply.py`/`entries.py`/`tucker_tensor_train.py`/`manifold.py` checked against the callee signature (frame tuple `(U,O,P,Q)` passthrough, `variation=(dU,dG)`, `(c, ww, frame, sweep, sop)`) — all correct.
- `sum_over_probes` semantics: `True == Σ_W(False)` holds (implicit in the per-`W` vs total adjoint checks; the `manifold.py` doctest checks it directly).
- `apply` with `W=()` vs `W=(1,)`: same value, shapes `()` vs `(1,)`; `probe` likewise.
- Entries index edge cases: duplicates scatter-add correctly (tangent + ambient); negative/out-of-range — see findings.

## Findings

### R5-1 (S, confirmed) — `entries_ambient_transpose` silently returns all-zero factors for negative indices, breaking its defining adjoint identity while `entries`/`entries_transpose`/`entries_corewise_transpose` all wrap negatives numpy-style
`t3toolbox/backend/entries.py:105` builds the one-hots as `xnp.arange(N) == index[i][..., None]`; a negative index matches nothing → zero factor. Forward `x.entries([-1,-2,-3])` returns the wrapped entry (= `xd[-1,-2,-3]`), the tangent transpose uses `eye(N)[index]` (wraps), the corewise transpose too, so the three siblings agree with the forward and the ambient one alone is zero. Under jax, an **out-of-range** index additionally makes the forward silently clamp (jax gather semantics) while the ambient transpose is again zero. Repro `r5_edge_cases.py` §C/§D: `ambient: <from_canonical(E^T c), x>_F = 0.0  expected c*entries = 16.29 ; ||T|| = 0.0` vs `tangent adjoint: -0.45376 == -0.45376`, `corewise adjoint: 22.4056 == 22.4056`. Supported path: the docstring says `index: int` only and the numpy forward accepts negatives without complaint; the dense check the doc gives (`X.to_dense()[index]`) wraps. Fix: build the one-hots with `xnp.eye(N)[index[i]]` (as `_onehot_vectors` does) — or validate `0 <= index < N` in the frontend `entries*` methods and document the contract.

### R5-2 (C, confirmed) — a Python-float residual crashes the tangent and corewise `apply`/`entries` transposes deep in `compute_sigma_hat` (`TypeError: 'float' object is not subscriptable`), while the ambient twin accepts `1.7` in its own doctest
`probing.py:834` does `c[..., None]` without `xnp.asarray`. `T3Tangent.apply_transpose(1.7, ww, frame)`, `T3Tangent.entries_transpose(1.7, idx, frame)`, `x.apply_corewise_transpose(1.7, ww)`, `x.entries_corewise_transpose(1.7, idx)` all raise; `TuckerTensorTrain.apply_ambient_transpose(1.7, ww)` works (its doctest at `tucker_tensor_train.py:3679` passes a bare `1.7`), and the tangent doctests conspicuously write `np.asarray(1.7)`/`np.asarray(2.0)`. A user copying the ambient example into the corewise call gets a TypeError five frames deep. Repro `r5_edge_cases.py` §A. Fix: `c = xnp.asarray(c)` at the top of `compute_sigma_hat` (or in `_apply_transpose_adjoint`).

### R5-3 (C, confirmed) — `MANIFOLD.project_ambient(frame, t3)` and `MANIFOLD.transport` crash at `d=1` (`IndexError: tuple index out of range`), while the dense path and `MANIFOLD.project` work
`tv_operations.tv_project_t3_onto_tangent_space` (`tv_operations.py:402`) calls `tt_zipper_left_to_right(cores[:-1], ...)` which indexes `coresA[0]` on an empty tuple. Reached from my scope via `project_ambient(frame, from_canonical(op_ambient_transpose(...)))` (the documented "tangent = projection of ambient" route) and from `transport`. `d=1` T3s are supported everywhere else (the test suite uses `((8,),(4,),(4,5))`). Repro `r5_edge_cases.py` §G and the sweep. Outside my module set (tv_operations) — flagging for the manifold lane. Fix: guard the empty-zipper case (return an empty tuple / skip the zipper when `d == 1`).

### R5-4 (C, confirmed) — `dense_probe` (public oracle, in `__all__`, used in doctests) crashes at `d=1` whenever the probe stack `W` is non-empty
`probing.py:1542`: the output subscript is `W_letters + C_letters + shape_letters[ii]`, but at `d=1` no vector is contracted, so the `W` letters appear in the output only → numpy `ValueError: ... output subscript 'b' which never appeared in an input`. `t3_probe` itself is fine at `d=1` with `W` (returns the broadcast `W+C+(N,)`). Repro `r5_edge_cases.py` §G: `x1.probe(W=(2,)): OK -> (2, 7)` / `dense_probe(W=(2,), d=1): ValueError`. Fix: when `ii` has no partner vectors, `broadcast_to` the result over `W` (or multiply by a `W`-shaped ones built from `vectors[0]`).

### R5-5 (C, confirmed) — `TuckerTensorTrain.entries` with a wrong-length **list** index raises `AttributeError` instead of the documented `ValueError`
`tucker_tensor_train.py:3380` formats the error with `index.shape[0]`; the docstring says the index may be "convertible to NDArray" and its own first example passes a list. `x.entries([1, 2])` on a `d=3` tensor → `AttributeError: 'list' object has no attribute 'shape'`; the ndarray spelling raises the intended ValueError. Repro `r5_edge_cases.py` §B. Fix: use `len(index)`.

### R5-6 (D, confirmed) — `tv_apply_transpose` / `T3Tangent.apply_transpose` docstrings describe the retired scatter implementation
`backend/apply.py:181-183`: "Needs only the frame sweep (xi-hat, mu-hat, nu-hat, eta-hat) and a single-term scatter assembly (it skips the adjoint perturbation sweep that tv_probe_transpose runs)". The code (`tv_precompute_apply_frame_sweep` → lean `(xis, mus)` only; `_apply_transpose_adjoint` → runs a reverse `sigma_hat` adjoint sweep; its own docstring says "replaces the old scatter") does the opposite on both counts. `manifold.py:781` repeats "frame sweep + a single-term scatter assembly". Fix: reword to "lean `(xi, mu)` frame sweep + one adjoint-state `sigma_hat` sweep".

### R5-7 (D, confirmed) — `TuckerTensorTrain.probe` return contract omits the frame stack and uses an undefined block letter
`tucker_tensor_train.py:3483` `# zz, len=d, elm_shape=X+W+(Ni,)` (`X` is not a block symbol; the order also reads frame-outer) and `:3497-3498` "each with `elm_shape=W+(Ni,)`". Actual (and the doctest three lines down prints it): `W + C + (Ni,)` = `(4, 5, 1, 2, 3, 14)`. Fix: `W+C+(Ni,)` in both places.

### R5-8 (D, confirmed) — `compute_mu` shape comment says `left_tt_cores: len=d-1`; every caller passes `len=d`, and passing `d-1` silently truncates the whole chain
`probing.py:220`. `t3_probe`, `tv_probe`, the sweeps and `tv_apply` all pass the full `d` cores (the scan discards the terminal carry). A backend user following the comment gets `len(mus)=d-1`, then `compute_eta` (a `ragged_map` over `len(xs[0])`) silently returns `d-1` etas — no error. Repro `r5_edge_cases.py` §H. This is the signature-style reference module. Fix: `len=d`.

### R5-9 (D, confirmed) — `docs/transposes.md:37` states the corewise transpose is the ambient back-projection "projected onto the core-parametrized tangent space"; it is the pullback `JᵀA`, not a projection
Checked with a dense corewise Jacobian `J` (columns = single-core perturbation tensors): `g_corewise == Jᵀ A` exactly, but `J g` vs the orthogonal projection `J J⁺ A` has relerr 18.7 (`‖JᵀJ − I‖ = 412`). The neighbouring sentence for the **tangent** transpose (line 39) is true (verified in the sweep via `project_ambient == project(𝒥ᵀ)`) precisely because that frame is orthonormal + gauged. Repro `r5_corewise_projection_claim.py`. Fix: "corewise = the ambient back-projection **pulled back** through the core parametrization (`J_coresᵀ`)".

### R5-10 (D, confirmed) — `docs/entries_apply_probe.md:220` points to `TuckerTensorTrain.{entries,apply}_transpose`, which do not exist
The frontend methods are `{entries,apply,probe}_{ambient,corewise}_transpose` (grep of `def .*transpose` in `tucker_tensor_train.py`). Also `:67` "Dense check: `result == X.to_dense()[index]`" only works for a single index tuple, not the documented `(d,)+W` array (needs `tuple(index)`). Fix: name the six real methods.

### R5-11 (E) — small things, all confirmed by reading
- `docs`/jax: under jax an out-of-range `entries` index silently clamps (forward + tangent) rather than raising as numpy does; undocumented (`r5_edge_cases.py` §D: `jax forward x.entries([7,0,0]) -> 2.8671 == xd[6,0,0]`).
- `probing.py:258, 453, 826, 942`: `reverse = tt_reverse if is_uniform else tt_reverse` — both branches identical (dead conditional, 4×).
- `entries.py:70,74`: `index = xnp.array(index)` twice.
- `probing.py` shape-comment notation drift in the reference module: `rRi` for the right bond at `:582, :621, :1125, :1220` vs `rR(i+1)` everywhere else (28 uses); `compute_sigma` `:393` column misaligned; `dense_probe` docstring lists parameters in the opposite order to the signature (`:1439-1444`); `tv_apply_transpose` `:173` says `c: W + C` though `K` is accepted (the `_from_sweep` twin says so).
- `manifold.py:666` "(V = the probe stack)" — the pre-rename letter (`K`).
- `t3_apply`/`t3_entries` have one-line docstrings with no shape/stack statement (the frontend carries it).
