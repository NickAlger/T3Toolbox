# Glossary candidates — scout C: frontend, examples, test docstrings, math notes

Scout C of three, 2026-11-10. Partition: every `t3toolbox/*.py` outside `backend/` (class, method and keyword
docstrings), `examples/*.py` (module docstrings and comments), the `tests/` module docstrings, and the math notes
`docs/*.tex`. The user docs (`docs/*.md`, `docs/*.rst`) were read only to choose link targets and to check that a
definition matches them. A backend docstring was read where the frontend defers to it (newton_cg's stats, history
fields and stop reasons; the Cauchy step).

**Conventions in the tables.**
- *Where* is the best place the term is defined or explained, as `file` › `Class.member` or `file` §heading.
- *Definition* is a suggested glossary text. Text in "quotes" is the docstring's own wording.
- *Link* is the page a glossary entry should point to. It is a user doc where one exists, named relative to `docs/`
  with its section (rendered at `nickalger.github.io/T3Toolbox/<page>.html`). `api:` marks a term with no user doc,
  where the API reference entry is the link.
- **(!)** in a row means the usage is inconsistent somewhere. The details are in the Inconsistencies section.

There are 185 terms: 177 numbered rows in sections A–K and 8 test-suite terms in section L. A list of terms with no
definition anywhere in the partition, the inconsistencies, and a table of symbol collisions follow them.

## Inconsistencies found

1. **The down frame core has three letters**: `D` in the `T3Frame` docstring (`down_tt_cores = (D0, …)`), `O` in the user
   guide, `frame_variations.md`, the tex notes and the paper, and "outer" in the user guide's minimal-rank list and
   `frame_variations.md`. Left/right are `L`/`R` in docstrings but `P`/`Q` in the paper notation, the tex, and
   `LocalModel` docstrings ("`X` = the frame's tensor `(U, P)`").
2. **Tucker core naming**: `B_i` (`TuckerTensorTrain`, user guide, probe diagrams), `U_i` (frames, tex), "Tucker factor",
   "Tucker basis" (`from_tensor_train`: "identity matrices for Tucker bases"), "leaf" (padded tex).
3. **Tucker factor orientation and TT-rank indexing in the tex notes**: `shared_t3_math.tex` uses `U_i ∈ ℝ^{N_i×n_i}` with
   orthonormal *columns*, and "TT ranks `r = (r_1,…,r_{d-1})`" (interior only). The code and the other notes use
   `n_i × N_i` with orthonormal rows and `tt_ranks` of length `d+1`. The tex modes are 1-based; the code is 0-based.
4. **Carrier naming**: "`Ld` and `R0`" (`T3Frame` docstring, `frame_variations.md`) vs `L_{d-1}`, `R_0` (padded tex) and
   `left[d-1]` (`aligned_padded_frame.md`). With cores numbered `L0…L(d-1)`, "`Ld`" does not exist.
5. **How many terms make a tangent**: the `frame_variations.md` heading says "a sum of `d` terms" (the Tucker set
   is a parenthetical). The `T3Tangent` docstring and `shared_t3_math.tex` say `2d`.
6. **`W` is called two names**: "probe stack" (`naming_conventions.md`, `batching_and_stacking.md`) and "sample stack"
   (`exact_hessian_two_hole.tex`, `UT3Tangent.probe_derivatives`, examples). `entries_apply_probe.md` says "probe /
   sample stack".
7. **`K` is reused against the 2026-08-24 ruling**: `examples/fit_hilbert_from_apply_derivatives.py` and `…_flat.py` write
   the highest derivative order as `K` ("`t=0..K`", "a vector of `K+1`"). Separately, the frontend `LocalModel` docstrings
   use `K_{Aᵀω²r}`, `K_{grad f}` for the curvature operator, which collides with the tangent stack `K` and puts `L`
   (left cores) beside `L` (the lift).
8. **The Jacobian is named three ways**: the user guide calls 𝒥 "the Riemannian Jacobian". `fitting.py` calls 𝒥 the
   "bare" Jacobian and `J = 𝒥∘Π` the Riemannian forward. `T3Tangent.probe` / `probe_transpose` say "the single-sample
   least-squares Jacobian `J^(s)`".
9. **Masks described as prefixes**: `UT3Masks` / `UT3FrameMasks` docstrings say "(the prefix/canonical form)". The user
   guide says "The masks are boolean prefix vectors rather than integer ranks" and "the first ni entries are 1", a few
   lines after explaining gappy working-form masks. Gappy masks are legitimate inputs everywhere.
10. **`numerically_equal` does not exist**: `TuckerTensorTrain.corewise_equal`, `UniformTuckerTensorTrain.corewise_equal`
    and `.allclose`, and `safety.comparison_rtol` all refer to a `numerically_equal` method. The method is `allclose`.
11. **The `g0_reference` value lists are incomplete**: the `newton_cg` signature comment lists `'zero' / 'warm_start'`,
    though the docstring accepts `'cone'`. The `NewtonInfo` docstring lists the history values as `'zero' / 'warm_start' /
    'override'`, but `'cone'` is recorded too.
12. **Typos in the core docstrings**: the `TuckerTensorTrain` class docstring has `tucker_ranks = (n0, r1, ..., n(d-1))`
    and its diagram labels the last mode `nd`/`Nd`. The `T3Frame` diagram has `Ud`.
13. **Stale "Gauss-Newton models" wording**: the package `__init__` docstring ("the Gauss-Newton fitting models") and the
    user guide's NumPy-and-JAX section ("the Gauss-Newton models") predate the `LocalModel` rename and `hessian='exact'`.
14. **"Best rank-r" for T3-SVD truncation**: `fit_hilbert_tensor_newton_cg.py` ("Relative error of the best
    rank-(tucker,tt) approximation of A (dense T3-SVD truncation)") and `fit_hilbert_from_entries_lbfgs.py` ("the best
    rank-`r` dense T3-SVD"). T3-SVD truncation is quasi-optimal, not best.
15. **`to_t3` / `from_t3` mean three things**: on `UniformTuckerTensorTrain` they convert between layers (same tensor). On
    `T3Frame` they map a point to its frame and a frame to its base point. `T3Tangent.to_t3` builds the doubled-rank T3 of
    the tangent. `UT3Frame.from_ut3` builds a frame at a point, not a conversion.
16. **"orthogonal" and "orthonormal" are interchangeable**: `is_orthogonal` checks orthonormality, and the docstrings mix
    "orthogonal frame" and "orthonormal frame".
17. **"lift" has two meanings**: the exact-Hessian lift `L` (gauged coordinates → raw core directions) and the probing
    step `z_i = U_iᵀη_i`, called "(lift)" in `symmetric_probe_derivatives.tex` eq. (z).
18. **"companion" has three meanings**: the geometry companion, the jet companion arrays, and "companion notes".
19. **"hole" has two meanings**: a variation slot in a frame diagram, and a core left out in the one-/two-hole sweep.
20. **"scatter" has two meanings**: the entries transpose ("scatter `c` at `index`") and the test helper that scatters
    ragged frames into uniform layouts.
21. **"base point" and "frame stack" mean other things in the derivative examples**:
    `fit_hilbert_from_apply_derivatives*.py` call the sample locations `X` "base points", and their stack "the frame
    stack starts as `(N_X,)`". The derivative-model docstrings call `ww` "probe vectors X" while `x`/`X` is also the T3
    iterate.
22. **"probe" is the operation, a noun and an adjective**: "a scalar per probe" for `apply`, "probe vectors" for the
    inputs of every kind, and "frame probe vectors X" (uniform probe-derivatives example).
23. **`weight=` vs weights** (documented, kept for compatibility): the residual weight ω is unrelated to the `*Weights`
    edge weights.
24. **`data` has three meanings**: the observed-values argument of the optimizers, the `.data` raw-core tuple, and
    "`data` — uniform UT3 data" as a parameter name (`naming_conventions.md`).
25. **"padded frame" is used loosely**: it is defined as old frame + completion, but `aligned_padded_frame.md`'s
    measurements also say "the library padded frame" for the geometry's own frame of `x0`.
26. **"project" covers four different maps**: `MANIFOLD.project` (gauge Π on coordinates), `project_ambient`,
    `project_oblique`, `SharedGeometry.project` (tied Π_sh), and the `project` callable argument of
    `fv_aligned_padded_frame`. "Projection onto the tangent space" can mean any of the first two.
27. **The forward operator has four letters**: `F(X)` (`LocalModel`: "`r = F(X) − y`"), `S(x)`
    (`fitting_and_optimization.md`, examples), `A X` (tex), `𝒥` on tangents.
28. **"basis" survives in import aliases**: doctests import `frame_variations_format as bvf` / `ubvf` / `ubcf`, a remnant
    of the retired "basis" name.
29. **`gtol`**: only `gtol_rel` exists.

## Symbol collisions a glossary should warn about

| Symbol | Meanings in the partition |
|---|---|
| `N` | mode size `N_i` (ragged `shape`); the uniform padded mode dimension; `N_X`, `N_P` counts (examples); the normal part (exact-Hessian tex) |
| `n` | Tucker rank `n_i`; the uniform padded Tucker rank; the measurement count in `batch/n` |
| `r` | TT rank `r_i`; the uniform padded TT rank; the residual |
| `K` | the tangent stack; the max derivative order (examples); the curvature operator `K_Z` (tex, `LocalModel` docstrings) |
| `W` | the probe/sample stack; a `T3Weights` instance in doctests; the up-matricization `W_i` (shared tex); the probe-vector tuple (probing tex) |
| `P` | the left frame core (paper/tex/`LocalModel`); the derivative direction (`pp`); the completion `P⁺` (padded tex); the tangent projector `P_X` |
| `L` | the left frame cores; the lift operator |
| `H` | the TT variations `H_i`; the Hessian `H`; the center `H_i = P_i ×₃ T_i` (exact-Hessian tex) |
| `S` | the sampling operator `S(x)`; the hint `S` (padded tex); the frame factor `S_i` (Gram factor) |
| `X` / `x` | the T3 iterate; the sample location of a derivative measurement (`ww` called "probe vectors X") |
| `T` | the frame factor `T_i` (exact-Hessian tex); the tangent space `T(F)` (padded tex); the represented tensor (shared tex) |
